# ASTaria

React + Vite + TypeScript + Three.js 应用，默认进入黑洞首页，包含本地事项、日程、平行宇宙和专注工作台。
原有业务界面可从 `/#/app` 进入。首页、工作台与日程共享析熙对话、本机任务和记忆。

## 技术栈

| 关注点 | 方案 |
| --- | --- |
| 框架 | React 19 + TypeScript |
| 构建 | Vite（`tsc --noEmit && vite build`） |
| 样式 | Tailwind CSS（`@tailwindcss/vite` 插件，`src/index.css` 中 `@import "tailwindcss"`） |
| PWA | vite-plugin-pwa，`strategies: 'generateSW'`（Workbox 生成 service worker），`registerType: 'autoUpdate'` |

## 命令

```bash
npm install     # 安装依赖
npm run dev     # 本地开发服务器
npm run build   # 类型检查 + 生产构建（输出到 dist/）
npm run build:preview # 设计预览构建（不注册新的离线缓存）
npm run preview # 预览生产构建产物
npm run typecheck
npm test        # 领域模型、本地数据库、AI 上下文和本机 API 的测试
```

工作台不再提供示例事项或旧的自定义入口，日程也不再单独放置黑白切换按钮；外观统一从「设置 → 外观与动画」调整。专注与休息时长在所有构建中均可调整。

## 析熙与本机数据

需要 Node.js 24.19 或更新的 Node 24 版本（使用内置 `node:sqlite`），以及 macOS Command Line Tools。开发和本地预览服务都提供同源 `/api`，请保持服务运行；单独打开 `dist/index.html` 或把静态文件托管到远程并不包含本机服务。

```bash
npm run dev -- --host 127.0.0.1 --port 5177
# 或构建后预览
npm run build:preview
npm run preview -- --host 127.0.0.1 --port 5188
```

在左上角 ASTaria → 设置中输入 DeepSeek API Key，选择「保存到钥匙串」，再「测试连接」。密钥通过本机私有管道写入 macOS 钥匙串，账号为 `dev.wason.ASTaria.deepseek / api-key`；不写入 `.env`、Git、SQLite、浏览器存储，也不向前端回显。服务固定请求 DeepSeek 官方 HTTPS 地址。首次使用会编译一个本机钥匙串助手，系统可能请求钥匙串访问授权。测试连接会产生少量 API 用量。

也可以在「设置 → 析熙 → 连接模型」切换到本地模型。支持本机 Ollama、LM Studio 和 OpenAI 兼容服务；地址只接受 `127.0.0.1`、`localhost` 或 `[::1]`，可读取已加载模型，也可手写模型名。保存后用「测试连接与工具」执行一次工具调用往返检查；没有通过工具调用的模型只适合普通问答，不应承担修改任务或日程。设备建议按系统内存给出轻量和推荐规模，但不替用户下载模型、不测推理速度，也不会在本地失败时偷偷切回云端。推荐使用支持工具调用的指令模型，并在本地服务中留出至少 16K 上下文（长对话建议 32K）。

设置中的默认模型可选择 DeepSeek Flash 或 DeepSeek V4 Pro，初始为 Flash，选择保存在本机数据库并跨浏览器共享。当前使用非思考模式。聊天按 Enter 发送、Shift+Enter 换行，中文输入法确认候选字不会误发；自己的消息即时显示，失败后可重试。析熙可以提出带快捷选项的问题，也支持自由输入回答。消息可复制，自己的消息可撤回；撤回后停止该轮后续处理并排除相关上下文，已执行的事项变更仍可从回执单独撤销。

黑洞渲染档位位于「设置 → 外观与动画」：满特效 120、满特效 90、满特效 60、轻特效 45、低特效 30。满特效档保持完整折射与 Bloom，低档保留整体视觉语言并降低渲染预算。首页与首页聊天按所选帧率运行；工作台及其他子页面自动将目标限制为 60 FPS。实际帧率受显示器刷新率与设备性能限制，页面隐藏时渲染会自动暂停；测试浏览器应在验证结束后退出，避免后台残留持续消耗 GPU。

数据存放于 `~/Library/Application Support/ASTaria/astaria.sqlite`，目录权限 0700、数据库 0600。同一 macOS 用户下的浏览器共用此文件。SQLite 保存任务、分类、日历、安排、对话、记忆、摘要、变更回执、推演、接力和正式设置；正在进行的专注计时与开发调参仍保存在浏览器中。旧浏览器业务数据首次打开后幂等迁移，源数据保留，旧 API 设置不会导入。若曾在旧界面保存过 API Key，请在迁入钥匙串后清理旧的 `astaria-settings` 浏览器数据库，并按需在 DeepSeek 控制台轮换旧密钥。

析熙可读取和拆分事项、设置截止与计划时间、修改状态、记住有原话来源的偏好。每次修改有回执，可以撤销；之后被手动改过的记录会保护性拒绝覆盖。临时记忆带有效期，任务记忆只用于相关任务。设置中可查看来源或忘记；相关来源及衍生上下文会被排除，原始聊天仍供回看。长期聊天使用有来源的摘要加最近完整轮次，并按需检索旧对话。

「设置 → 析熙」可调整个性强度：低（简洁温和）、中（自然俏皮）、高（小得意、有点小腹黑，底色温柔），默认高。保存后从下一条回复开始生效，不必新开对话；各档只调整表达，与主动权限、提醒频率、记忆开关独立。设置随本机数据持久化并进入备份。

人格底色位于 `server/prompts/persona.md`，三档表达由 `server/personality.mjs` 按当前设置选取，工作与工具协议位于 `server/prompts/working.md`。请求时按需选取对话、记忆、任务与日程资料交给 DeepSeek。测试使用虚拟 provider 和临时数据库，不需要真实密钥或付费请求。

上下文在每次实际请求前统一计算预算，包含实时钟表、工具定义和待完成事项。较长的旧对话与工具结果只压缩发送副本，原文保留在本机；省略的读取明确标记为未读全，不能当成空闲。多项明确时段分别核验；中断提示列出已保存与尚未完成的部分，重试接续原请求。全部已核验的排程即使最后文字回复超限，也可用本地回执确认，不重复执行。

析熙新建事项后会直接根据真实空档安排日历，不再先问是否安排。按已有估时分配；未给用时时先预留 30 分钟，并注明可修改。安排避开课程、休息、已有任务和锁定时段，遵守明确日期、可用窗口及截止时间；空档不足会列出剩余未安排部分。“只记录、先不安排”和设置中的“先提出方案”仍会保留原日程。任务和本次自动安排在同一事务提交，撤销创建也会撤销关联的自动时段；后续手动修改仍受版本保护。

指定钟点的新事项可通过 `create_tasks` 的每项 `schedule` 与 `expectedRevision`，在读取日程后把事项和时段一起保存；冲突时一起回滚。兼容分步创建的调用，每项日历义务独立核验：移动考试成功不能代替社团活动入历，明确日期和时段按实际记录检查。未完成时继续执行，失败保留重试，撤销后的安排不会自动复活。默认日程上下文将“晚自习”等窗口与占用者、实际剩余时间一起提供；后续日程和截断计数保持可辨，全天占用分钟数不代表某个任务的用时。

聊天的创建事项回执下方提供「今天／明天／后天／日期与时刻」，直接修改原事项的 DDL；可快捷选择 08:00、12:00、18:00、20:00 或全天，也能自定义分钟和清除日期，不需要再次聊天或重新创建。更新同步工作台与日程；若新 DDL 早于已有时段，会提示调整计划。每轮工作单分别记录工具提交、未完成部分和回复状态；已提交的完整操作遇到回复生成失败时，会用本地事实回执收口。

## 日程与安排

从左上角 ASTaria 进入「日程」。月视图观察截止日期与忙闲分布，周视图显示课程、固定活动、休息、空课与任务时段，日视图展开一天的完整时间线。月／周／日切换保留选中的日期，并展示对应日期的可支配时间与出门准备。任务的截止日期和安排时段分别保存，移除时段会保留任务。旧启动设置中的日历、时间表自动映射到日程。

导航始终向右展开，窄屏可在栏内横向滚动，也可用方向键、Home／End 导航。日程页面将当天信息集中在顶部横向概览，下方主视图使用整行宽度；768px 及以上唤出析熙时，聊天与主视图并排；更窄时使用固定抽屉，标题和输入框不随聊天记录滚走。Esc 可收起聊天并返回触发按钮，跨尺寸切换保留输入草稿。时间表中的空课用金色边框表示，点击整块或按 Enter／空格即可编辑。临时调课日也可点击课程、休息或空课编辑来源的每周安排，窗口会说明影响范围；保存后同步今天和未来的相关调课日，历史记录保持不变。来源已被移除时保留历史只读内容，并提供当前每周安排入口。

日程按内容完整展开，统一滚动整个页面查看下方日期与晚间时段，主玻璃板内部不再上下滚动。窄屏的周视图保留横向滚动；日视图使用单列时间线。

首次使用默认加入周一至周五 18:00–20:00 晚自习，可自行修改。项目内的旧课表需要点击「载入旧课表」，由用户核对课程、空课与时间，也可自己录入；载入时保留已有晚自习与自行添加的安排。未记录的空白不计为空闲，可支配时间只统计明确的空课或自习，并扣除固定活动、休息及已安排任务。核对完成后可点击「已核对完成」，之后仍可编辑每周安排。目前支持每周重复课表，尚不支持隔周课表。

点击课程可记录地点及所需物品；点击任务可填写准备说明、携带物品、是否需要提交，并添加或锁定时段。出门清单会汇总当日需要的物品，保留来源及「建议」标记。完成任务与确认提交是独立状态：已经做完但还没提交的事项仍会提醒，实际提交由用户确认，也可撤回确认。

指定钟点或修改现有安排时，析熙通过 `read_planner` 读取目标日期起最多 7 天的安排，再用 `plan_tasks` 保存时段。安排会检查日期版本、时区、过去时间、重叠、DDL 和锁定状态；未知空档需先确认，锁定时段需用户在页面解锁。AI 的 `startAt` 仅表示日期意向，精确钟点统一由排程工具处理。新增会议与其他任务顺延可同批提交，按最终布局检查冲突并原子保存，可整体撤销；排程回执返回实际保存的时段。`remove_plan` 移除未锁定时段，`save_task_preparation` 保存明确的准备信息，操作均提供可查看、可撤销的回执。站内可见页面会根据未读变更、真实空闲和准备清单显示通知；尚不提供关闭应用后的系统通知、定位或设备感知，析熙立绘尚未接入。

## 推演、接力与牵挂

从左上角 ASTaria →「平行宇宙」进入独立页面，与工作台、日程并列。选择一件真实事项，比较「今天优先完成」「先做一小段」「今天先放下」三条路径；拖动时间尺，从当天看到一年，按住对照按钮即可暂时查看原安排。黑洞复用现有渲染器，直接改变吸积盘形态、光线弯曲和离盘运动，退出后恢复首页视角。控制、结果和时间尺分别放在独立玻璃片上。

近期推演依据明确空闲、DDL、估时、锁定状态和缓冲生成 7 天内的候选安排；缺少用时或无法排下的部分会明确列出。「只这一次」的影响不会凭空累积；「假如每周如此」按首周的实际分配计算条件性投入，不预测成绩、完成率或人生结果，也不会写入远期日程。草案保存在本机，预览不改变日历，明确采用后才整批保存，并可整体撤销；任务或课表版本变化时须重新推演。

专注页按计时、任务步骤、析熙聊天排列。在右侧聊天粘贴作业要求，析熙可以把当前任务拆成可勾选的步骤，保留每一步的材料与提交要求。中间清单显示完成数量、进度和下一步，较长清单分页查看。勾选或取消勾选后立即存入本机数据库，再次进入、刷新或换浏览器都会恢复；重新拆分保留已有进度。明确给出当前任务的具体明细时，析熙直接保存对应步骤，条目数量与顺序按用户提供的内容保留。全部勾选不会自动完成整项任务或确认提交。析熙写入步骤有可撤销回执，后续手动勾选会保护进度，阻止旧回执覆盖。

左侧玻璃板在专注和接力之间切换，中间始终保留任务步骤。点击与专注按钮并排的金色药丸「留个接力」会暂停计时，在同一面板记录进度、卡点、下一步和材料；保存后回到计时界面并显示接力摘要，继续计时由用户决定。返回专注会保留未保存草稿，已保存的记录下次进入可恢复。切换只移动玻璃内部内容，玻璃本身保持不动。接力与牵挂保留原话来源和版本，AI来源撤回时衍生记录退出上下文。

牵挂清单保存尚未成为任务的愿望，可编辑、暂停、恢复、移除或设置有效期。机会提示依据真实空闲，所需物品及其他条件仍需用户确认；未提供用时时暂按30分钟试留并注明估计。它不会自动创建任务或占用日程。

## 设置与黑洞回应

设置使用独立页面，分为通用、析熙、记忆、时间安排、通知、外观与动画、数据。可调整启动页面、自动执行/先提方案、记忆和历史的上下文使用、默认专注休息、排程缓冲、晚自习和周末可安排时段、免打扰、网格、玻璃预设和信息密度。记忆可更正或忘记；变更有未读记录。数据页提供无API Key的JSON备份和显式确认恢复，恢复会使旧方案及旧操作快照失效。

「外观与动画 → 玻璃与空间 → 卡片装饰线」提供左右对称、仅左侧、隐藏，默认左右对称。课程、安排和同类小卡片沿用各自状态色，金色可安排框和选中轮廓保留；设置保存在本机数据库并跨浏览器共享。

「外观与动画」提供光潮、弦光、引星、关闭，以及轻柔/标准/鲜明强度和减弱动态。默认光潮·轻柔。预览时收起设置内容以展示黑洞，返回时通过退场动画恢复原滚动位置与焦点，退场同时释放玻璃折射和阴影。预览不调用模型；发送消息时对应真实请求的思考阶段，整段回复到达时呈现约4秒回复反馈，随后自然平息。现有API为整段返回，并非流式输出。特效由明确的渲染接口传入，idle/off恢复原始盘面；相机、观察距离、视界形状和鼠标引力不变。

模型偶尔将提问工具输出为 DSML 文本时，服务会将完整的单个提问恢复为问题与快捷选项。截断、混合或未知的协议内容会显示可读错误，不执行文本中的写操作；旧消息读取时也会修正显示，保留原始存储。

上下文组装优先保留当前请求和相邻四轮对话，再分配次要资料的空间。历史工具负载转换为精简操作记录，保留任务 ID 与问题选项；较长原文保留检索来源，撤回、忘记和关闭历史使用的边界继续生效。

## 结构

```
index.html            入口 HTML
vite.config.ts        Vite + Tailwind + PWA 配置（manifest 名称：ASTaria）
tsconfig.json         TypeScript 配置
src/main.tsx          React 挂载入口
src/App.tsx           原有业务界面
src/home/             黑洞首页、析熙面板与日程概览
src/workbench/        专注工作台、持久化步骤清单与 Upcoming DDL
src/planner/          日历、时间表、空闲容量、任务时段与出门准备
src/xixi/             析熙聊天、设置、记忆与变更记录
server/               本机 SQLite、钥匙串、AI 工具与提示词
src/prototype/        黑洞渲染核心
src/index.css         Tailwind 入口
src/vite-env.d.ts     Vite 客户端类型
public/               静态资源与 ASTaria 图标
```

构建后 `dist/` 中会生成 `manifest.webmanifest` 与 `sw.js`（generateSW 产物）。
