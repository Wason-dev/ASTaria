# 渲染与后台性能

当前必须保留的帧率、省电、后台生命周期与画质取舍，集中记录在 [省电与渲染决策记录](./POWER_AND_RENDERING_DECISIONS.md)。工作区最高 60 FPS 是用户确认的省电策略；首页/聊天保留手动 90/120 FPS 选择。以下按版本保留优化历史，不能把解除省电上限计作收益。

beta.3 的优化不降低原有分辨率、辉光、采样质量或特效强度。重点减少没有必要的 JavaScript、网络轮询和内存分配。

- 共享设置订阅、忽略内容相同的数据快照；专注计时仅在运行阶段刷新。
- 页面隐藏时移除轮询计时器，返回时刷新；弦轨组详情隐藏时取消动画循环。
- 弦轨复用曲线采样容器与路径临时点；只有变换或路径变化时才写回 DOM。
- 黑洞帧记录使用固定容量循环缓冲区，避免持续移除长数组首项；重复画质配置不再重建帧调度。

2026-09-29，以同样的临时数据库、独立 Chrome 配置和减少动态效果设置，对比 9 月 28 日优化前构建与 beta.3 源码。前台首页空闲 20 秒：

| 软件指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 250 ms 计时回调 | 80 | 0 |
| 15 s interval 回调 | 2 | 0 |
| React 提交 | 9 | 0 |
| 设置读取请求 | 2 | 1 |
| 任务／会话读取总数 | 8 | 8 |

前台仍保留必要的数据刷新。以上对比涵盖两阶段优化的累计效果；不等于第二阶段单独收益。减少动态效果条件用于隔离后台工作量，并不代表动画开启时的 GPU 成本。软件渲染测试不能推出真实 Mac 功耗、温度或续航百分比。

复现：桌面构建后运行 `node scripts/verify-idle-performance.mjs`，通过 `IDLE_QA_BASELINE` 指向原基线构建。测试只操作临时数据库和浏览器，不操作现有数据。弦轨几何、辉光连续性和动态边界由 `scripts/horizon-renderer.test.mjs` 验证。长期硬件功耗与不同屏幕刷新率仍需实机测量。

## BetaX：Windows 玻璃材质取舍与实测

BetaX 对 Windows 上玻璃边缘折射的处理是一次**明确的材质取舍，不是无损画质优化**：默认走 CSS 通透/磨砂路径，保留 rim、tint、通透与磨砂差别，但不做 SVG 精细边缘位移（`src/home/glassRendering.ts` 的 `supportsGlassRefraction` 在 Windows 上返回 false）。设置里可以单独选「精细折射」换回 SVG 位移，代价是可见的帧率下降（见下表）。**黑洞本身的最高画质、渲染分辨率、采样与辉光没有被降低**；Windows 与 macOS 都不因这一取舍改变黑洞画质档位的定义。

### 2026-10-05 · Windows 10 19044 · RTX 4090 Laptop · D3D11

环境：Windows 10 x64（19044）真实交互会话，RTX 4090 Laptop，D3D11，GPU 合成、栅格与 WebGL 均已启用；2560×1400 CSS、DPR 1.5，实际黑洞渲染 3824×2091 ultra。每个样本 8 秒，`desktop/performance-smoke.mjs` 采集。表中数字是采样的 `renderFps`（真实渲染帧），不是 `requestAnimationFrame` 回调频率。

| 场景 | 旧实现 | 默认新实现（CSS 玻璃） | 同构建 · 精细折射 |
| --- | ---: | ---: | ---: |
| 工作台 | 37.30 | **59.99** | 40.91 |
| 余时 | 21.48 | **59.98** | 23.24 |
| 首页 | — | 59.97 | 59.99 |
| 余时（浅色 · 磨砂） | — | 58.61 | — |

- 「旧实现」指同机同参数的 Windows 早期构建；「默认新实现」固定黑洞最高画质，并使用 BetaX 默认玻璃路径；「同构建 · 精细折射」是同一份 BetaX 构建把设置切到「精细折射」后的对照，用来证明上表差额来自玻璃路径而不是其它改动。
- 首页在两种玻璃路径下都接近 60 FPS：黑洞渲染本身没有减速，差异集中在工作台与余时的玻璃合成。
- 余时浅色·磨砂 58.61 是最低的默认配置样本，仍接近 60 FPS 目标。

### 复现方式

```bash
# 桌面构建后，用一次性 profile 与数据库跑性能采样（不会打开真实数据）
ASTaria.exe --smoke-test --measure-performance      # Windows
/Applications/ASTaria.app/Contents/MacOS/Electron --smoke-test --measure-performance   # macOS
```

`--smoke-test` 建立一次性临时目录与临时 SQLite 数据库，`--measure-performance` 在其中依次切换「深色·通透」「浅色·磨砂」「深色·通透·精细折射」，对首页、工作台、余时各取样 8 秒，输出 `ASTARIA_PERFORMANCE_SAMPLE` 行、`performance.json` 与逐场景 PNG（含 `app.getGPUInfo` 与 GPU feature 状态）。

### 限制

- 只有一个 GPU 与一种分辨率/DPR 的结果；不同 GPU、驱动、屏幕刷新率与电源模式可能差异很大，不作为所有设备的承诺。
- 8 秒样本只反映短时前台负载，不构成长时间功耗、温度、风扇或续航结论。
- 不把 `requestAnimationFrame` 回调频率（如 160 Hz 显示下的回调计数）当作黑洞帧率；判断标准始终是渲染帧。
- 精细折射在 Windows 上属于高开销选项，默认关闭；macOS 不受该默认影响。

## Beta11：保留省电预算的双平台动态优化

2026-10-05，本地候选；未推送或上传 GitHub。目标是减少切页与聊天形变中的无用工作、误跳帧和长帧。工作区最高 60 FPS 的既有省电策略保持不变；首页/聊天保留手动 90/120，30/45 不升档，手动画质独立。原因与回归边界见[决策记录 P01–P07](./POWER_AND_RENDERING_DECISIONS.md)。

### 本版实际改动

- 高刷 RAF 时间戳容差从 0.25ms 调为 2ms；绝对截止时间仍按完整间隔推进，避免误跳帧，不提高平均目标 FPS、不补画过期帧。
- 相同有效帧率和画质的切页保留帧调度与自适应历史；预算确实改变（如首页 120→工作区 60）时正常重新调度。
- 相机几何快照、SVG 属性去重；同尺寸且 RGBA 逐字节相同的位移图复用 PNG。比较缓冲最多一张、上限 8 MiB；原位移公式、分辨率不变。
- CSS 玻璃不创建无用 SVG 和尺寸观察器；零半径 blur 使用 none。通透/磨砂、色调、边缘、反光、阴影参数保持原值。
- 浅色精确端点的 bloom 贡献为零时跳过三个中间 pass；指针强度精确为零时跳过无贡献计算，任何非零值都保留原效果。
- 工作台、日程、余时的既有 200ms 退出淡出结束后跳过隐藏布局，返回恢复可见内容、编辑状态与滚动；不卸载保留页。
- Mac 打包优先 APFS 克隆，降低临时文件占用。这是构建优化，不计入 App 运行性能。

### 画质和状态核对

- Mac 与 Windows 各 16 组真实 GPU 对照冻结的 BetaX 着色器，覆盖日夜 0、接近零、中间、1，以及指针 0、接近零、中等、1。本轮两端最大颜色通道差均为 0；这不保证其他驱动也逐位相同。
- 位移图用独立完整 RGBA 参考检查；每端另取 12 张深/浅 × 通透/磨砂 × 聊天/工作台/余时截图，均无文档横向溢出且仍为 ultra。
- `none` 与 `blur(0)` 的整页截图对比不作为逐像素等同证明：CSS 合成边缘/文字会有取整差异，Windows 首组还出现指针附近的未冻结变化，产生局部大差值，具体触发原因未完全隔离。该图只用于人工布局/材质复核，不能将其像素差归为单纯的边缘误差，也不能替代独立 GPU 对照。
- 两端都验证退出淡出中可见、结束后隐藏、返回立即可见、DOM 节点相同、滚动保留和快速返回。手动 120 档在首页/聊天为 120、工作区为 60、返回首页为 120；保存档位仍为 120。

### 复现与测量限制

```text
ASTaria.exe --smoke-test --measure-interactions --interaction-repeat --verify-render-equivalence --verify-interaction-visuals
ASTaria.app/Contents/MacOS/Electron --smoke-test --measure-interactions --interaction-repeat --verify-render-equivalence --verify-interaction-visuals
```

所有原生诊断只在 `--smoke-test` 的一次性数据库和 profile 中运行。为避免系统遮挡暂停使样本失效，交互诊断临时将测试窗口置顶，结束后恢复；正式运行仍保留系统与 App 的后台省电机制。`--interaction-quick` 只测默认配置，不能替代完整矩阵。源码测试包括省电档位往返、相同预算调度、抖动、相机去重、位移图、GPU 分支及原有后台/专注测试；本轮完整测试 1,494 项通过，Windows 同代码专项 63 项通过。隔离浏览器的 `scripts/verify-response-settings.mjs --render-policy-only` 通过 52 项当前设置检查；旧综合预览流程尚未整体迁移，不能宣称该脚本默认路径全量通过，具体见 [交接边界](./BETA11_HANDOFF.md#开发验收脚本边界)。

本轮每平台仅一台设备和短时样本，不是统计显著性或全设备保证。基线与候选的 GPU query 探针实现有调整，因此不发布微小 GPU 时间差的收益比例。早期同时运行另一个 BetaX 实例的结果、磁盘已满时的异常、取消省电上限的中间构建以及 Mac 被遮挡而没有 RAF 的片段均未作为本表证据。最终安装包需独立启动验收，见 [Beta11 说明](./RELEASE_NOTES_v0.1.0-beta.11.md)。

**尚未解决/验收：** Windows 首次展开聊天的偶发长帧、手动精细玻璃高开销、Windows 11、更多 GPU/DPI/多屏、休眠恢复、长时功耗/温度/续航。不能由上述结果宣称 Windows 全程流畅或省电百分比；真实模型下载和推理按用户要求未执行。
