# ASTaria 界面与交互规范

> 状态：Beta 8 起的 UI 设计基线。面向产品设计、前端实现、代码评审和后续 AI 协作。
> 本文描述应达到的体验；文末列出的旧实现偏差不构成新界面的参考。

## 1. 如何使用本文

ASTaria 是本机优先的时间与事项工具。视觉主题是「时间有引力」：安静的宇宙场景、真实透光的玻璃、克制的金色反馈，以及可核对的具体安排。它首先是每天反复使用的工作界面，其次才是场景和动画。

做 UI 改动前，先看[当前首页截图](images/home.png)、[有回执的首页](images/home-receipt.png)、[日程周视图](images/planner.png)、[调课日视图](images/planner-day.png)、[余时](images/free-time.png)、[弦轨](images/horizon.png)、[工作台](images/workbench.png)和[工作台专注聊天](images/workbench-focus.png)，再读对应页面的实现。截图是视觉参照，不是像素模板；其中的虚构数据仅为演示。设置和首次引导暂时没有经过验收的固定截图：应在运行中的正式入口查看其当前组件及深色/浅色、通透/磨砂状态，不能凭旧版截图或单一 CSS 片段猜测。实际入口是 `src/main.tsx` 默认加载的 `BlackHolePrototype` / `HomeWorkspace`。`#/app` 指向的旧 `src/App.tsx` 不作为当前设计基线。

冲突时按下列顺序判断：

1. 用户当前明确提出的目标、行为和约束。
2. 本文对产品风格、状态和交互的要求。
3. 同一页面已经稳定使用的组件和令牌。
4. 邻近页面的可复用模式。
5. CSS 中偶然留下的字面量或旧版实现。

本文不要求一次性重构全站。改某一处时，把那一处的主题、玻璃、状态和动效做完整；不要为了“统一”顺手改动无关页面或黑洞渲染。新增视觉语言若确有必要，应先解释它为何比现有语言更适合该任务，并同步更新本文。

## 2. 核心气质

**安静但有深度。** 大场景留白，小信息精确。黑洞、地平线和折射提供空间感，控件保持轻量。页面不靠很多发光点、渐变团、悬浮装饰卡或彩色块制造“高级感”。

**透明但可读。** 玻璃要让背景可见，边缘和反射让材质成立，内容仍有稳定对比度。透明不等于消失；磨砂不等于灰白蒙版。用户选择通透或磨砂后，所有主要面板都应继承这一选择。

**有引力的连续空间。** 从首页进入工作台、日程、余时、弦轨时，用户应知道自己从哪里来、到哪里去。背景、空间位置或共享元素应有连续线索。退出是进入的逆过程，而不是突然换一张画面。

**操作优先。** 首屏直接呈现可用的任务、日历、对话或当前场景。空态简短；不把功能说明、调试提示和键盘提示长期放在界面显眼位置。真实状态、结果、撤销和失败恢复比装饰性文案重要。

**克制的个性。** 金色只负责选中、焦点、可操作边缘、少量时间提示与场景光。主要文字是暖白或深石墨色，次要信息是中性灰。红绿等语义色只在确实区分状态时少量使用，不成为页面主色。

## 3. 页面与信息架构

| 区域 | 首要任务 | 空间和密度 | 标准交互 |
| --- | --- | --- | --- |
| 首页 | 看当前、和析熙说话、核对变更 | 黑洞是第一视觉信号；周围留白；对话和当天日历同处一个空间 | 左上品牌展开一级导航；聊天展开/收拢保留上下文；回执可展开和撤销 |
| 工作台 | 从「现在可以开始」进入专注 | 比首页更密集，面板服务于扫描和执行 | 明确任务状态、步骤、截止与专注入口；返回后焦点回到合理位置 |
| 日程 | 看课程、活动、任务、真实空档 | 月/周/日视图适配宽空间；时间列对齐 | 日期和视图切换保留方向感；新建、完成和调整反馈真实保存状态 |
| 余时 | 管理持续目标、心愿和未来安排 | 宽面板与横向内容优先；目标和已排时间可对照 | 「安排」必须反映实际写入；变更可核对和撤销；堆叠内容用按钮横向浏览 |
| 弦轨 | 聚焦一天，审视日期、组和顺序 | 事件视界/地平线是空间主轴；周围控件退后 | 日期、分组、跨组移动、收拢、保存有清晰连续状态；避免每次进入无谓重新整理 |
| 设置 | 修改外观、析熙、通知、更新等 | 宽空间使用成组的两列或自适应网格；各列底边和控件宽度有秩序 | 控件保存、忙碌、失败和禁用状态可辨；外观预览不破坏当前页面 |
| 首次引导 | 完成最少量的个性化，认识主要区域 | 首页场景仍是空间背景；一片主玻璃承载短步骤 | 可跳过密钥配置；设置要明确保存；教程结束后进入真实产品 |

一级导航保持简单，子任务留在所属页面。命令入口用文字或图标加文字；局部工具按钮用清楚的图标和 tooltip。页面标题、内容左边界和首行基线保持一致：当前公共边界参考 `src/ui/workspace-heading.css` 的 `1320px` 内容最大宽度、桌面 `88px` 顶部和窄屏 `72px` 顶部。标题不是英雄文案：工作区标题约 `24px`，窄屏约 `22px`；小面板标题按信息层级缩小。

不要把全页切成一层又一层卡片。页面区块可以是无框的排列、细分隔线和留白；真正的玻璃外壳用于主区域、模态框或独立工具。重复的事项卡可以有轻薄内板，但不要在一个重玻璃卡里再叠多个重玻璃卡。

## 4. 色彩与主题

ASTaria 有正式的深色与浅色主题，且两者都支持「通透」和「柔和磨砂」。不能只验证默认深色通透。`src/xixi/preferences.ts` 保存 `theme: dark | light`、`glass: clear | soft`、`density: compact | comfortable`、卡片装饰线等偏好。当前默认是深色、通透、小巧。UI 不应在页面之间重置这些偏好。

| 语义 | 深色参考 | 浅色参考 | 用法 |
| --- | --- | --- | --- |
| 主要文字 | `#eeeae3` | `#30343a` | 标题、正文、操作名称 |
| 正文次级 | `#d4d0c9` | `#55616b` | 说明、次级内容 |
| 弱化文字 | `#bcc0c7` 附近 | `#626b75` 附近 | 时间、元信息；仍须可读 |
| 分隔线 | `#e1ded526` 附近 | `#4146501c` 至 `#41465026` | 1px 内板边线和区块划分 |
| 交互金 | `#d5bb8b` 附近 | `#927443` / `#a58752` 附近 | 选中、聚焦、可操作边缘；小面积使用 |
| 玻璃底色 | `rgb(8 10 14 / var(--glass-tint))` | `rgb(250 251 252 / var(--glass-tint))` | 透光外壳，不是整页不透明遮罩 |

这些是**语义锚点**，不是要求一次性把每个旧 hex 都替换为同一个值。新组件优先读所在页面的 `--p0-*`、`--wb-*`、`--pl-*`、`--ft-*`、`--settings-*` 等页面令牌；若缺某个语义，先在页面层补齐，再由组件读取。避免在组件深处硬编码另一套“金色”。旧全局 `:root` 中的蓝色变量来自历史界面，不应成为新 ASTaria 页面的默认强调色。

浅色不是深色加白色蒙层。浅色时同时调整文字、面板底色、边界、阴影、状态色和 `color-scheme`；去掉深色文字阴影。玻璃应有可见但轻的外投影和清晰高光，尤其在白背景上，不能看起来像消失了。强制颜色模式需要可见边界和焦点，不能仅凭透明高光表达状态。

## 5. 玻璃材质合同

### 5.1 三层结构

一个标准玻璃面板包含：

1. **取样层**：采样背后的真实场景，产生轻微模糊和边缘折射。
2. **材料层**：跟随宿主圆角的透明底色、细内高光与 1px 渐变边缘。
3. **内容层**：文字和操作位于材质之上，不被模糊，也不跟着边缘滤镜扭曲。

优先复用 `src/home/GlassSurface.tsx` 的 `MeasuredGlassSurface` / `GlassSurface`。宿主圆角必须同时约束取样、材料和内容裁切；这能避免玻璃轮廓与下方按钮或面板圆角不一致。当前 Chromium 使用 SVG backdrop 位移，其他引擎回退到 blur；不应为每个内层列表项再生成一套独立折射。`src/planner/planner-glass.css` 展示了外层真实取样、内层轻量半透明 plate 的分层方式。

玻璃的“真实性”来自背景在边缘发生细微折射、内侧有一点反光、在合适主题下有阴影；不是整片 20px 的磨砂白，也不是一圈常亮金边。反光要跟随材质，不横跨整页。悬停或键盘焦点时，金边亮起并稍微提高对比；离开后平滑回落。静止时边缘仍足够让面板被辨认。

**日程弹层与内板的材质约束：** 事项与安排、每周安排、记录事项、导入课表和 ICS 共用日程玻璃的填充、网格、圆角、边线和主题响应。内板使用低对比的局部网格与平直底色，不使用跨面板中心的斜向反射或持续辉光；交互高亮只作用于当前被指向的控件，离开后回落，不能把整个面板照亮。

**Windows 的材质取舍（有意为之，不是无损优化）。** `src/home/glassRendering.ts` 的 `supportsGlassRefraction` 在 Windows 上默认返回 false：Windows 走 CSS 通透/磨砂路径，保留 rim、tint、反光、悬停金边，以及通透与磨砂的差别，但不做 SVG 精细边缘位移。设置 → 外观与动画 → 玻璃渲染可以选「精细折射」换回 SVG 位移，代价是明显的帧率下降（实测数据见[渲染与后台性能](./PERFORMANCE.md)）。**这一取舍只影响玻璃边缘位移，黑洞的最高画质、渲染分辨率、采样与辉光不变**；玻璃精细度的取舍必须在设置中可见，不能把它记作同画质性能提升。滚动容器在 Windows 使用 8px 主题滚动条：透明轨道、中性圆角 thumb、悬停少量金色、无上下箭头，深浅主题都可见。

**2026-10-15 Android 自动玻璃：** Android 的「自动」同样使用系统 CSS 通透/6px 磨砂，保留高光、边缘、阴影与主题响应，手动「精细折射」仍在支持 SVG backdrop 的 Chromium 中可用；iOS/WKWebView 继续使用原有 CSS fallback。此选择独立于黑洞的自动/手动画质，不改分辨率、采样、辉光或帧率。默认少了玻璃边缘位移，是已批准的材质取舍，不计作无损提速；手机原生视觉与功耗仍待设备验收。

**手机排版与构图（2026-10-15）：** 聊天正文为 13px、行高 1.7，Markdown 标题限制在 13–14px，保留 10–11px 的短元信息层级；Android 编辑控件为 14px，iOS 编辑控件为 16px 以避免聚焦自动缩放，不能把所有手机控件一律抬高。窄屏黑洞中心向右偏移，展开聊天时随相机放大连续增加偏移，使中心黑色阴影主要位于右半部，左侧保留吸积盘。星点、点击入口和弦轨投影共享实际相机坐标，退出时恢复对应构图；横屏与桌面沿用原映射。构图是明确的视觉调整，不是性能收益。

### 5.2 两种偏好

| 模式 | 目标 | 当前入口 |
| --- | --- | --- |
| 通透 `clear` | 保留场景细节，边缘折射可察觉；文字对比靠适量 tint 和局部内板保障 | 偏好映射为 `blur: 0` |
| 柔和磨砂 `soft` | 背景细节稍退后，轮廓、反光和场景仍在；不是纯不透明灰色 | 偏好映射为 `blur: 6` |

切换模式时，首页、工作台、日程、余时、弦轨相关按钮、设置和弹层的**主要玻璃外壳**都应响应。尤其检查从一个页面进入另一页面、面板打开/关闭、内容加载完成后是否突然变成纯透明或纯磨砂。内部 plate 可以为了性能使用固定的半透明材质，但它与外壳在色温、边线和明暗上应像同一种材料。

复用玻璃组件本身**不会自动继承**外观偏好：未传 `material` 的 `MeasuredGlassSurface` 会落到 `HOME_GLASS` 默认值（其中 `blur: 2`），而现有个别弹层和弦轨控件仍传固定材料。新建或调整外壳时，必须从当前偏好显式导出材质参数，并逐一检查主面板、按钮、弹层和预览是否随模式改变。不要把组件的默认材质误当成 `clear` 或 `soft` 的实现。

`HOME_GLASS` 和 `DEFAULT_APPEARANCE` 是不同使用场景的当前参数，不是覆盖全站的唯一数值表。通透度、rim、shadow、radius 等调试参数可以在既有外观系统中调节；新功能默认要继承用户偏好，而不是创建第三套隐藏的默认材质。

**手机玻璃深浅是独立偏好：** `glassTone: light | dark` 表示底色浓淡，不能用改 RGB 为白色来实现“浅”。默认淡档沿用原主题 RGB（深色界面 8/10/14，浅色界面 250/251/252），降低着色 alpha；深档提高 alpha。它与界面主题、通透/磨砂分别保存，切主题不改该偏好，磨砂仍按原 6px 执行。手机主面板、菜单、上下文、对话记录、事项集合、选择器、导入和首次设置读取同一个填充变量；首次引导本地预览也使用同一档位。旧配置缺字段默认淡档，已有明确选择保留。桌面成熟材质参数不在这次手机浓淡调整范围内。

### 当前渲染执行约束

调整渲染、动效或后台生命周期前，先读[省电与渲染决策记录](./POWER_AND_RENDERING_DECISIONS.md)，其中列出触发条件、历史证据和回归检查。

**Beta12.1 转场时序：** 页面目的地改变不能立即触发降帧；相机弹簧仍运动时沿用保存的首页帧率（默认 60，手动 30/45/60/90/120），直到相机实际停稳才应用工作区 30 FPS 上限。输入提前就绪阈值不代表转场已结束。快速反向和恢复窗口也按真实相机状态判断，不用固定延时猜测。

帧率分区是有意的省电设计，不是缺陷：Beta12 按用户决定把工作台、余时、日程、设置的黑洞与环境渲染上限从 60 改为 **30 FPS**。首页与聊天的推荐档仍以 60 FPS 为目标，手动 30/45/60/90/120 选择继续生效，返回首页恢复所选帧率；保存的选择和独立手动画质不被改写。降低工作区背景帧率牺牲时间流畅度，不能算同画质同帧率收益，也不是对 DOM、CSS 动画或输入的全局锁帧。历史 60 FPS 策略保留在决策记录中。

重复相机快照、相同 SVG 属性与逐字节相同的位移贴图不应反复写入/编码；CSS 玻璃不创建不可见 SVG，零半径模糊使用 none。位移图按几何变化更新，静止几何不重复生成；背景仍运动时浏览器仍需合成实时 backdrop，不能宣称整个工作区 0 FPS，或已有独立的可变刷新折射控制器。隐藏工作区可在退出淡出结束后跳过布局，但必须保留编辑状态、滚动位置和快速返回行为；可见时不额外建立影响玻璃取样的 containment。测试须同时覆盖 Mac 与 Windows 的动态过程。

### 5.3 几何、层级和性能

主玻璃外壳可用较大的圆角（当前工作台、余时和设置约 `20–24px`），内板通常约 `10–16px`，密集条目约 `6–10px`；图标圆按钮才使用真正的圆。相邻边缘要共享几何逻辑，间距要相同。不要把“圆角更大”当作提高质感的通用办法。

只有少量最外层面板实时取样。滚动列表内部使用边线、轻渐变、上缘高光和浅阴影来表达材质。隐藏页面、退出中的面板和不在视口内的重玻璃应停用不必要的采样；动画尽量变换内容层的 `opacity` / `transform`，避免逐帧重新计算整块 backdrop。尊重当前 `GlassSamplingContext` 等生命周期机制。视觉测试应同时观察帧率和 GPU 占用，不能只看一帧截图。

## 6. 排版与版式

ASTaria 的文字是密集、细致而清楚的工作型排版。正式入口 `.p0` 当前使用 `Inter`, `Helvetica Neue`, `PingFang SC`, sans-serif；旧全局 `:root` 另有 `Microsoft YaHei` 等回退，不应以旧入口的字体覆盖正式界面。中英文和数字混排时要检查基线。数字时间使用 `tabular-nums`，避免时刻变化导致跳动。常见正文为 `12–13px`，辅助信息 `10–11px`；小字号只用于短元信息，长句与错误说明应比元信息更易读。不要在面板里用首页级大字，不要为了“未来感”引入难读的显示字体。

选择间距时先保持局部网格：紧凑元素常用 `4/6/8px`，普通控件与行用 `10/12px`，主区域之间用 `16/24px` 左右。这里是设计阶梯，不是每个地方必须同一个 gap；在同一行、同一列、同一组重复组件中必须一致。宽空间要利用横向比较与并列信息：设置可用两列，日程可用时间视图加侧栏，余时的多项内容优先横向分页或切换。不要在宽面板中央堆一条窄窄的竖列。

所有固定格式元素（日期格、卡片栈、工具栏、计数器、圆按钮）都要有稳定尺寸或约束，加载和 hover 不可推挤周边。长中文标题允许合理换行，长英文或路径允许 `overflow-wrap:anywhere`；只有确实为单行扫描的元信息才省略号截断，并提供可读取完整内容的途径。窄屏上先保住主要操作和文字，再让次级列重排，不允许遮挡、横向溢出或按钮文本被裁断。

## 7. 控件语言

| 目的 | 使用方式 | 不应出现 |
| --- | --- | --- |
| 明确命令 | 文本或图标加文本按钮，如保存、安排、撤销 | 把导航/工具伪装成大号营销 CTA |
| 工具动作 | 熟悉图标按钮，`aria-label` 和 tooltip 说明含义 | 用一串圆角文字胶囊代替标准图标 |
| 二元设置 | switch / checkbox | 把开关藏在模糊的“模式卡片”里 |
| 多选一 | 分段控件、tabs、select，取决于选项数量 | 为三个短选项各建一张大卡 |
| 数值调节 | slider / stepper / input，显示当前值与单位 | 只有视觉变化、没有可核对数值 |
| 颜色选择 | 色样或明确颜色名 | 用色名胶囊代替可见色样 |

按钮默认轻、边界细，hover/focus 才提高金色存在感。按下态、选中态、禁用态、忙碌态不应只靠亮度区分；必要时加入图标、位置或文字。禁用必须说明原因，或在上下文中自然可理解。相同动作在不同页面使用一致的动词。删除和撤销不是同一件事：删除需清楚标明对象和后果；已执行的安排尽可能提供本轮撤销入口。

点击目标要与视觉目标一致。圆形按钮的图标应位于**实际圆心**；hover 区域不能导致按钮消失、位移或命中断裂。鼠标、触控板、键盘都应可完成核心操作，但不要仅把横向浏览交给触控板手势；可见的前后按钮仍要存在。使用现有图标库时优先复用，保持笔画粗细一致。

## 8. 动效与空间转场

ASTaria 的动效帮助用户理解状态与位置，不是一直让界面“活着”。小控件反馈通常约 `160–260ms`，内容切换常见 `300–400ms`；跨空间的弦轨进入与退出有自己的长时序。现有模块已有不同曲线和时长，不应机械加一个全局毫秒数。设计新动效时先画出开始、经过、结束三态，再定时长。

1. **进入**：原入口仍可被识别；放大或飞行时保留共享场景、方向或材质线索。浅色模式不能在一帧内把黑色背景压重。
2. **停留**：场景运动与信息布局各司其职。黑洞和地平线是背景主角，文字、按钮、玻璃不会无故漂移或持续晃动。
3. **组内切换**：顺序、焦点、标题与光带一起连续变化；不整屏闪黑，不像跳到另一个页面。
4. **退出**：先让当前内容按层退场，再显现返回 UI 与原页面；背景亮度不能先压暗再突然变亮；文字不应比所在材质晚很多才消失。
5. **状态切换**：高度变化与内容出现协调；不突然把文字抬高。必要时使用 FLIP 或局部 GSAP，但避免为简单 hover 引入复杂时间线。

动效必须支持 `prefers-reduced-motion` 和现有用户设置。减少动态效果时保留状态区分，用短淡入或直接切换，不保留飞行、视差或晃动。动画中的控件仍需处理输入：防止重复提交、重复开启模态框、退出时点击穿透。页面隐藏、窗口恢复、渲染档位变化也要检查动画是否卡住或从错误的中间帧继续。

## 9. 反馈、析熙与真实进度

**2026-10-18 首页输入区收敛：** 移除「只记为事项」及旁路保存入口。沿用 `HomeWorkspace` / `conversation.css` 的现有输入布局：左侧模型与上下文圆环，右侧图片 ＋ 和「发给析熙」；不补一个替代按钮，不修改宿主玻璃、字号和动效。“只记录、不安排”仍可通过析熙表达，日程的记录事项和已有回执、撤销能力不受影响。

**Beta12.1 图片输入约定：** 首页与工作台「专注」共用简洁输入形态。输入框上方不放「图片」工具栏；「发给析熙」左边是带可访问名称的圆形 ＋，图标居中，继承宿主文字、分隔线和交互金。已选图片的预览、读取状态或错误提示只在对应状态下出现在输入框下方。拖图进入 ASTaria 时，优先给当前专注聊天，否则打开首页聊天，仍需主动发送。设置、弹层和忙碌状态不接受拖入，普通文字拖动保留。图片读取、换图竞争和失败不能导致误发旧附件。两处输入均需覆盖深浅色、通透/磨砂、窄屏与键盘焦点。

涉及任务、日程或目标的写操作，界面要区分「建议」「准备保存」「已经写入」「写入失败」「结果不确定」。不要把模型建议画成已经提交的安排。回执说明实际创建、修改或删除了什么，显示具体日期与时间，并提供合适的撤销。估时与已排时长不同，应并列展示，不能让旧的 30 分钟回执看起来仍代表当前 45 分钟估计。

**Beta12 回执交互约定：** 析熙正文、未完成提示和变更回执分别承担对话、执行状态和已保存事实的职责。部分失败不能用固定清单覆盖模型回复；独立提示只列「尚未完成」，沿用当前主题的细分隔线、次级文字与少量金色，不增加一层玻璃卡。排程回执标题用动作与数量，日期和起止时间只在明细列一次；保留未估时的暂定预留说明与撤销入口。模型回复中断时清楚标为系统状态，不伪造析熙的回复；模型声称完成也不能改变实际的失败或部分完成状态。

**本地 v1.0 候选的估时与空档约定（2026-10-14）：** 创建事项回执的快捷估时（15 / 20 / 30 / 45 / 60 分钟与自定义，无清除）不是本地直接改估时的开关。选中后把内部操作请求发回原对话，并带上该回执自身的事项 ID。该自动请求保留用于执行、核对和重试，但不显示成“你”发出的聊天气泡；发送中、历史与刷新恢复均遵循这一规则。前端呈现析熙依据实际结果自然生成的回复和真实回执，不能把用户提供的回复示例写成固定模板；在收到真实结果前，界面不显示新的估时，也不把这条请求写成已经调整。析熙读取最新日程后调整同一事项的估时和排程、检查冲突，不改动其他已经确认的安排，信息不足时先提问。回复完成后必须核对真实事项与已排分钟：只改了估时、没有排程，或只有口头说明而没有实际写入，都要明确显示「尚未确认」或「尚未同步」，不能用模型措辞代替实际状态。输入草稿与附件保留，重试沿用原请求 ID。DDL 入口仍是本地直接保存，不因估时请求挪动时段。

**弦轨空档选择约定（2026-10-14）：** 只有今天当前空档的剩余时间放不下完整事项、且本地检查确认可按每段至少 15 分钟分段可行时，才出现「析熙安排」选项：先用空档分段、保留完整一段、先不改。三个选项同级，可用键盘聚焦和确认，焦点可见、Tab 顺序与视觉顺序一致；整段排不下时不出现整段选项。选项本身只是建议：做出选择之前不写日程、不发执行回执、不调用模型，文案和视觉都不能让人以为安排已经保存。选择后仍显示真实阶段（模型核对、本地终检、整批保存），保留总时长、日期、DDL、顺序与固定占用，新增段与原段一起撤销。重复事项与余时目标的单次安排不拆分。

等待时显示**真实执行阶段**，例如读取、拆解、核对、搜索、排程、保存；阶段来自真实事件，不按固定时间轮播文案。能并行的读取可以并行，但状态不应夸大已完成工作。中断或断线后，先核对本机回执再显示结论；重试不应重复创建。无论进度条还是轨迹列表，都沿用玻璃、弱金和中性色，不冒出默认绿色进度样式。

析熙原有「思考过程」默认折叠，用户仍可展开、收起并复制完整思考；增加等待标题不得移除这些功能。模型返回完整的 `【进度】…` 短标题时，只替换思考阶段三个跳动点右侧的「正在思考」，沿用原状态文字颜色；没有有效标题时保留「正在思考」，不能截取普通思考正文冒充标题。不加「模型曾／模型正在」等前缀，不新增金色标题区；正文开始输出后移除小标题，历史回复不重复展示。课表识别等待时继续显示整理图片、模型读取和结果核对等真实阶段。

发送进入等待状态时即呈现思考入口，收到首段思考内容只更新内容，不新增一行推挤布局。复制操作的「正在读取／已复制」在按钮原位替换文字并保留宽度；成功提示不另起一行，读取或复制失败的具体说明仍须可见。

模型没有给出进度标记时，可使用同一已选模型对当前有限片段异步生成活动摘要，仍只替换原状态文字。摘要请求与主回复独立，采用非思考短输出，每条用户请求最多四次、每轮最多两次；不等待它才回复，不改变主对话的思考深度或输出预算。正文到达、工具执行、轮次结束、撤回或取消后，取消摘要并丢弃迟到结果；不保存到历史，也不把未经核实的完成结论当作进度。

空态要告诉用户当前没有什么、下一步能做什么，语气简短。错误要解释具体失败点和恢复动作。成功提示可以短暂出现，但重要操作结果不只依赖会消失的 toast。加载占位尺寸稳定，避免面板频繁伸缩。产品文字不出现示例预览、开发调试、内部工具名、系统指令或无意义的 Esc 提示。

**上下文圆环（2026-10-18）：** 首页与工作台输入区共用 `ContextMeter`，小圆环与模型名并列，非加载动画。DeepSeek 满环按1,000,000 tokens计算；显示最近一次实际请求（输入含资料/工具，输出包含在内），不能累计所有历史账单或缓存命中数字。来源为接口用量或明确标注的估算，切换模型/新话题/撤回后不混用旧结果；未知自定义模型窗口保持未知。详情区分应用压缩预算和模型窗口；浮层严格参考首页点击事项的 `TaskDialog`，复用 `MeasuredGlassSurface`、19px圆角、关闭按钮与动效，禁止实色黑底。后方界面保留可见，通过任务详情同款轻遮罩与前景模糊建立层次，不能隐藏底层内容或切换原玻璃取样；关闭恢复焦点；鼠标、键盘可打开/收起，关闭有退场过程。

## 10. 输入、键盘与可访问性

**析熙表格与公式（2026-10-18）：** 共用 `MessageMarkdown` 渲染首页、工作台专注和历史回复。Markdown 表格直接融入原聊天玻璃，继承正文颜色和字号，以轻表头、行间距、细横线表达结构；不添加深色实底、重外框、斑马纹或第二层玻璃。数学排版使用随应用打包的字体，支持行内/独立公式、分式、上下标、根号等，不能让公式撑破聊天宽度；宽表/长公式只在自身范围内滚动且能键盘访问。数学引擎按需加载，未完成或无法解析的公式保留可读原文，不以报错打断回复；完整复制仍是模型原始文本。模型正文与历史不被排版规则改写成固定模板。

所有可操作元素必须有可见焦点、语义标签和一致的键盘行为。紧凑控件可以用内缩焦点环，但不能简单 `outline:none` 而没有等价替代。模态框打开后焦点进入正确位置，关闭后回到触发元素。Escape 按层退出：先取消拖动/编辑，再收拢组，最后退出弦轨；保存进行中要避免误关闭。不要为了展示“Esc”而常驻一段提示字。

弦轨空档方案尚未确认时不写日程、不产生执行回执或调用模型。「先不改」或 Escape 返回调整，保留当前草稿并恢复「完成」按钮焦点；取消退出弦轨沿用既有语义，丢弃未保存草稿，原日程不变。估时选择后会立即发送请求，沿用聊天的忙碌和重试规则；等待时不乐观更新，已经实际保存的部分也不能因关闭界面被视为撤销。

纯颜色或纯光晕不是唯一状态信号；配合文字、形状、图标、选中边框或位置。`aria-pressed`、`aria-current`、`role=status`、`aria-live` 与真实状态同步。较小的视觉控件在粗指针设备上扩大命中区域，不能只放大装饰边框。深色、浅色、通透、磨砂、强制颜色、减少动态效果和键盘导航都属于正式验收矩阵。

## 11. 各页面的具体边界

**首页**：黑洞是可见的空间锚点，左上品牌导航和右侧场景不互相抢焦点。展开对话时，它与当天安排属于同一张玻璃/同一个空间，不突然变成独立重面板。变更回执和撤销必须能在真实数据状态下阅读。点击黑洞进入弦轨的命中区要稳定，不能覆盖周边按钮。

**工作台**：优先让用户知道现在可做什么、什么时候截止、如何继续。专注界面简化控件，保持析熙反馈可见；删除任务等动作应在可预期位置，不为了“极简”藏到找不到。大量事项使用可辨的堆叠和前后按钮，不能只有上下长列表。完成状态与日程、余时使用同一数据结果。

**日程**：时间刻度、课程、活动、任务与空档保持几何准确。月/周/日选择与日期切换是明确的分段和箭头控制。空档可点击区域覆盖真实时段；拖动或 hover 的发光不能改变时段位置。侧栏与聊天打开时使用真实布局轨道，不让文字躲在玻璃下面。

**桌面日视图（2026-10-18）**：沿用用户给出的单天横向课表参考，将课程、活动、任务与已知空档放在同一条横向日程中；仅真正时间重叠的项目在对应时段上下并列。不得按类别拆成四个纵向大区块，也不得为标签的最小宽度另起多行。共享时段边界决定各格位置，短课间紧凑、长空白压缩；每项保留准确起止时间，短空档可通过聚焦/悬停读取完整时间。保持原有面板顺序：当天概览主面板在上，横向日视图在下；日视图自身不再把整天内容堆成需要纵向滚动的长表。提醒和日期截止不虚构占用时段。复用日程主题、玻璃与双向日期动效，手机日程保持独立排版。

**余时**：持续目标的频率、预计用时、已排时长和次数可对照。目标、心愿、排程与安排情况保持同一材料家族。一个事项较多时用可见按钮左右浏览；宽屏内容充分使用横向空间。安排按钮只有实际保存后才显示成功，失败时保留上下文。浅色与磨砂模式下各面板都要有存在感。

**弦轨**：一天是一次沉浸式焦点。事件视界的圆弧与光带必须几何对齐；日期、组、事项围绕同一条地平线组织。组名默认可见，选择组、跨组移动、收拢、退出有连续动画和明确结果。背景运动服务于深度，不压过文字。组数超过一屏时前后箭头的可见圆形与命中区域同心。再次进入尽量复用仍有效的结果，不无条件重新做智能分组。智能过程展示真实动作和阶段。

**设置**：选择项少而明确，同一组控件宽度一致、列边界与底边有秩序。外观、模型、通知和更新使用同一套浅/深主题及玻璃材质。高级调试参数可在调试入口存在，不把它们全堆到日常设置。更新进度采用 ASTaria 材料与配色；「可写目录」等技术信息需翻成用户可理解的操作建议。

**首次引导**：它是一次性的任务流程，不是营销落地页。首屏显示当前快捷设置摘要，「保存并继续」一次保存；外观、性格、帧率与画质的详细控制按需展开，后退或导入返回保留选择。截图导入课表与 ICS 入口在首屏直达。帧率与画质可选「ASTaria 推荐」或手动分开设置，沿用既有平台画质与环境帧率规则。模型步骤先解释本地部署、API Key、聊天会员与 API 计费，再提供 DeepSeek 官方网站和密钥页面的分步链接；帮助按需展开，API Key 使用密码框，不回显、不进日志或截图。桌面可进入其它 API/本地模型设置，手机明确显示支持范围。没有密钥也可稍后配置，随时可直接开始。

功能导览默认收起为紧凑提示，可展开/收起；不改变正在介绍的页面宽度、不自动把工作区压缩到左侧、不为提示预留右侧整栏。提示折叠状态和真实操作反馈分开处理，介绍不能遮住唯一目标按钮。

**课表导入**：使用日程既有的玻璃、文字、主题和间距。截图先出草稿，总课表先问「你选的是哪些课？」；按科目分组展示去重后的原始代码，数字、大小写与写法不改，`Econ1`/`Econ2` 分开。选定代码匹配全周，再按需要问分组并复用答案。最后以「代码 · 星期 · 节次 · 教室」编辑确认，每项可改或删，教室次要且可空；教师不提取、不展示。节次钟点来自表头，缺失时允许按节次统一补齐；未知格子必须可见，不猜、不静默丢弃，不把红线、虚线框和日期角标当课程。用户确认才保存，显示真实结果和可撤销回执。ICS 同样先预览再写入，不能为了减少点击省去确认。窄屏横向表格允许独立滚动，主要操作和错误可找。

介绍到工作台这一步时，引导必须如实反映工作台的四种状态，不能把任何一种说成另一种：读取中说明「仍在读取，也可以先继续」，读取失败说明「暂时未能读取，可在工作台重试或先继续」，读到的确是空工作台才说「现在没有可开始的事项」，有真实事项则要求打开一项再返回，并且只有真的打开并返回后才显示「已完成这一步」。这四种状态都以真实数据为准，不在引导中伪装已创建事项或已连上模型；所有步骤均可跳过；空态、加载和失败状态直接提供「继续」。整个流程使用同一块主玻璃和稳定的步骤位置；切换内容不改变外壳几何，后退保留已选内容，完成后进入真实首页。窄屏允许内容滚动，进度、主要操作和错误信息始终可找。引导的主题与玻璃选择也必须同时影响自身材质；不能预览一个外观，保存后得到另一个。

## 12. 实施流程与验收

每次新建或改动 UI，按下面顺序工作：

1. 定义页面所属区域、用户任务、主次操作和可能状态；查看对应截图与组件。
2. 先画静态布局，确认宽/窄视口的边界、文字、命中区和滚动，再接玻璃材质。
3. 让主题、通透/磨砂、密度、减少动态效果贯穿该组件及它的弹层。
4. 接真实数据和真实写入阶段；处理空、满、加载、失败、成功、撤销和重复操作。
5. 补键盘与焦点流程，再设计入场、状态切换和退场。
6. 在真实运行页面截取深色与浅色、通透与磨砂、桌面与窄屏的对照；检查动画首尾帧和中间帧，不只看最终静态图。
7. 验证性能：滚动与切换时没有成排 live backdrop 采样，没有不必要的重算或掉帧；画质不因“优化”被默默削弱。

评审时至少问：这是不是 ASTaria 当前页面的一部分？文字和操作是否先于特效？玻璃在两种材质、两种主题下是否都成立？对齐、圆角、间距、投影是否一致？hover/focus 是否清楚而不过亮？切换和退出是否连续？真实保存与可撤销结果是否可信？键盘和减少动态效果是否完整？

## 13. 现存偏差与演进方向

当前 CSS 不是一份已经完全统一的设计系统。部分页面基座默认深色，工作台部分规则基座默认浅色；`data-theme` 与根场景的 `data-night` 并行。页面强调金、弱化文字、浅色玻璃底色有多个近似值；部分旧规则硬编码透明度，可能盖过用户外观设置。`src/planner/planner-glass.css` 与布局样式有局部重复选择器。这些是后续改动要**逐处收敛**的偏差，不是新页面可以复制的自由度。

演进优先级：先保证用户四种外观组合都正确，其次让同一语义在页面间一致，再逐步收敛令牌和 CSS 来源。迁移时保留视觉回归截图与交互回归；不要为了追求单一令牌导致弦轨失去沉浸感、首页失去留白，或工作台失去可扫描性。

## 14. UI 交付门槛：可读、分层与操作过程

源码测试、类型检查、构建成功和截图数量不能证明 UI 合格。它们只能作为各自范围的证据。新增或重做页面必须逐项完成下面的视觉与操作验收；未完成必须标记「待检查」或「待真机」，不得用总测试数替代。

### 文字与信息组织

- 每屏先明确用户此刻要完成的一个任务，再展示当前步骤所需内容。课表导入使用互斥的「选择图片 → 选择课程 → 必要时选组 → 核对 → 保存结果」，未识别时不显示空的课程选择、分组和核对区。回退保留原图、草稿与选择。
- 标题、说明、值、错误和主操作必须一眼可辨，不在同一区域堆叠两层说明或重复结果。次要帮助按需展开，不能把必需信息藏起来。
- 中文不能挤成单字纵列；320 px 视口下检查长标题、长课程代码、大字体、数字和错误换行。正文在背景最亮处仍可读，不能只在纯黑区域看似清楚。
- 行高由文字与控件决定。并列栏按内容从上向下排列，不用均分高度、撑满父栏或空的 grid 轨道把三项设置拉成几屏。宽屏保留合理阅读宽度，空白需要服务于分组或操作，不能是布局副作用。

### 材质与层级

- 浮层以首页任务详情为参照，保留原页面玻璃、内容和位置，通过轻遮罩与前景模糊建立层次。不得隐藏底层采样却留下独立可见的文字，也不把底层文字当作清晰前景展示。
- 打开弹层时，底下页面由模态层阻止交互，画面仍可见；不能隐藏底层玻璃或包含弹层自身的祖先。关闭后恢复原页面位置、焦点与数据，背景层连续。
- 不用全不透明黑板代替正确分层。通透和磨砂仍属于同一材料家族，深浅主题都要检查最亮背景位置的对比度、边界与选中态。
- 禁止带有浏览器默认灰色方框、系统白色选项大菜单的临时控件混入正式界面。二态设置使用产品开关，整行命中且明确开/关；互斥选择使用按钮组或清晰的单选列表。保留 role、aria-checked/pressed、焦点与禁用原因。

### 动画与触达

- 打开前确定外壳几何，入场只做合适的短位移/淡入，不能先缩一帧再展开、闪出未布局内容或先显示底层文字。切步、返回、关闭都需要连续过程，减少动态效果时直接完成。
- 检查初帧、中间帧、终帧，连续打开关闭、反向操作与快速切步也要检查。不得只截动画结束后的静态图就宣布「流畅」。
- 检查真实命中：选择/开关整行可点、文件选择能返回、禁用有明确原因、处理中的操作不可重复提交。不能只对元素调用 click 而不确认它是否被遮挡。
- 返回入口跟随实际导航层级，避免无意义的右上「返回」与重复关闭；手机使用一致的左上返回位置，子页返回上层，主导航负责页面间切换。

### 手机保留同一视觉语言，独立组织交互

手机重排不等于更换视觉语言。保留原首页黑洞周围的留空、下方当前任务和「交给析熙」、品牌入口、细线胶囊和圆形图标控件、轻字重与克制暖金；不擅自加入大号口号、实色主按钮、统计卡堆叠或通用移动仪表盘。减少重复信息，不能用内容填满原有的高级留白。

- 手机复用原首页、品牌导航、聊天展开、弦轨、字体与真实动效组件，不仿写另一套外壳或新增析熙导航。共享业务模型、保存和回执规则；通过独立的手机日程排版、设置分层与页面生命周期减少信息负担，不能只把整张桌面表格缩小。
- 系统状态栏已有时间，不在每个手机工作页重复桌面日期时钟。当天日期只在相关的日程/今日上下文出现，减少信息噪声。
- 背景布局尺寸与键盘可见区域分离。IME 出现时只调整当前消息/编辑前景，不能重新缩放黑洞、把所有页面向上挤，不能将输入框放在键盘下。
- 不可见页面不持续生成玻璃图、测量布局或绘制 WebGL。暂停被遮挡且不可见的渲染需记录范围；不把降低可见画质、模糊背景或提高功耗预算称为无损优化。

### 最终验收记录

每个交付页面至少留下：深/浅 × 通透/磨砂、桌面与 320/390 px（适用时）、空/有内容/长内容/错误/处理中、键盘打开关闭、入场/切步/退场的证据。说明实际看过的画面、发现并修复的问题、仍未完成的设备检查。脚本断言与人工视觉判断分别记录；必须审阅实际截图，而非只看截图文件生成成功。

### 事项集合（2026-10-20）

同主题、同一 DDL 的多份作业保留独立事项 ID、原始代码、估时、安排和完成状态，首页 DDL、当天事项和工作台列表以一张集合摘要显示。主题归属必须来自明确 collection 字段或用户手动归类，不能仅按同日期、人名、编号或学科猜测；分批创建 8＋2 不拆成两个集合。摘要只列名称、份数/完成数、共同 DDL 和剩余估时，共同备注不逐项重复。

图标与集合名必须在同一行。集合详情复用 `FloatingGlassDialog`、`floating-glass-dialog.css` 和现有事项详情的文字/控件基线：桌面居中约 760px 宽，左右两列利用横向空间，十项尽量一屏展示；窄于 620px 收为单列，正文内部滚动，页头和底部操作独立。列表按真实安排时间排列，未安排明确标出，单项点入后沿用原事项操作。手动归类支持筛选、多选、整批版本检查、保存与撤销，不新增深层路由。

首页 DDL 与当天事项中的集合行保留普通事项左侧同尺寸、同位置的圆点，使用当前主题的中性色；文件夹图标位于圆点右侧、名称旁边，不能代替圆点，也不把集合内各项的状态强行归成单一事项状态。

同轮对话中同集合的创建回执默认收拢，明细和各项 DDL/估时编辑按需展开；每个原操作保留自己的撤销边界。自然语言回复不得替换为集合模板，部分失败提示不能因为收拢而消失。

共享浮层只保留一层贴合圆角的中性内轮廓，不叠宿主 border、材质 rim 和外置描边。圆角、采样和轮廓使用同一个零外边框盒，按设备像素定位。浮层保留后方界面与原玻璃，按任务详情的轻遮罩和自然模糊建立层次；不隔离、隐藏或替换底层取样。共用进场参考工作台专注：360ms `cubic-bezier(.16,.8,.25,1)` 内容位移 9px，材质/轮廓约 350ms；关闭使用同曲线和有限时长交接，始终不缩放采样面或文字。首页收起胶囊和展开面板的取样必须裁在真实圆角内，不能只依赖SVG取样叶层的border-radius；投影保留原位置与参数。

## 15. 相似功能优先复用成熟面板

实现相似功能前，先找到应用内已经成熟的同类界面，说明具体组件与样式来源，优先直接复用，再做最小适配。不能因为页面、平台或实现者不同，就重新定义一套字体、按钮、选中态、边框、材料、尺寸和动效。子代理派单与验收也必须遵守此规则；只引用“ASTaria 风格”这句话不足以构成设计基线。

| 新需求 | 优先参考与复用 |
| --- | --- |
| 任务/内容详情弹层 | `HomeWorkspace.tsx` 的 `TaskDialog`、`home-task-dialog`：保留后方界面，轻遮罩和自然模糊建立层次，前景保留折射 |
| 每周安排、单日活动及类似编辑 | `PlannerDialogs.tsx` 的 `PlannerDialog`：同一外壳、标题、表单节奏、保存/错误与退场；不另造全屏手机表单 |
| 设置分区与控件 | 原 `LocalSettings`、`settings.css`、`ModelConnection`：继承原字号、轻字重、胶囊动作与开关 |
| 导入等多步确认流程 | `ImportSurface` 与已有编辑面板：复用材料和进出生命周期，分步组织内容，不将每一步做成另一种软件 |
| 选一个值 | 在原界面上方浮出紧凑选择层，选定即返回；保留原界面周围的上下文，不新增路由层级、整页标题或新的“返回”页面 |

同类弹层的最大宽度、圆角、页头、内容边距与按钮高度使用共同规格。内容长时由面板内部正文滚动；内容少时自然高度，不强制撑满屏幕。打开前景后保留原面板、边框、投影及页面上下文；用任务详情同款轻遮罩表达前后关系，不给底层挖洞。

| 区域 | 覆盖的面板 | 必须沿用的基线与验收 |

选择层只保留一套清晰状态：选中以轻底色与勾号表示，键盘焦点落在实际活动选项上；列表容器不额外画金色矩形，不叠两三重描边，不让边线贴住文字。手机设置六入口使用占满主玻璃的单列列表：一行一项、左侧统一线性图标、标题居中于行高、右侧轻箭头，以细分隔线而不是六张小卡建立层级；余时标题与分类、日程标题与视图切换在同一行内对齐。

所有面板打开、关闭、返回和内容分区切换均需真实的入场与退场过程；退场完成才卸载，减少动态效果是明确例外。只写入场 keyframe、立即卸载旧内容，不算完成双向动效。验收必须对照成熟参照的实际画面和中间帧，发现分裂先回用现有组件，不继续叠加新风格补丁。

### 15.6 手机工作区跨页一致性

手机排版以余时目标面板的留白、可读性和原有胶囊操作为共同参照。工作台、日程、余时、设置的一级标题在主要玻璃外；小节标题留在玻璃内。手机公共外壳规则由 `mobile/runtime/mobile.css` 的 `--m-panel-*`、`--m-*-size` 和单一 `mobile-workspace-scene` 管理：当前主玻璃圆角 20px、内容左右留白 16px，主要内容 13px、操作标签 12px、短元信息 11px，小节标题 14px，一级标题沿用 WorkspaceHeading 的 22px。不能把不同信息层级全部设成同一个字号，也不能通过增大字体补偿材质或合成造成的模糊。iOS 编辑控件仍保留防自动缩放的 16px 例外。

主玻璃在同一主题下共享填充；通透与磨砂继续通过用户偏好控制取样模糊。不能在某个页面再加深或提亮一层整页底色，或由 lazy CSS 恢复另一套固定填充。各页使用相同的手机滚动条合同，避免桌面自定义滚动条保留不同宽度的 gutter，令边界错位。相同材质不表示每一帧像素亮度相同：不同位置仍透出真实背景，但填充、边缘和遮罩的来源应相同。

动画结束后，内容层和祖先应恢复正常排版平面，不保留只为入场创建的 transform、opacity 或 will-change。切换目标、已安排、心愿时，只过渡变化的内容，共用玻璃与不变的弦轨入口保持稳定。验收要对照四页的实际截图、文本与边框距离、正文祖先的稳态样式，以及切换的开始/中间/结束帧；源码计数与构建通过不能代替这些检查。首页持续闪边仍须独立复现和验收，不能由跨页一致性检查推断已修复。

手机 SVG backdrop 在实际场景里需要显式失效旧缓存时，依照省电决策 P22 订阅真实出帧通知；不得通过变化光学几何、重做位移图、动画文字或额外常驻刷新循环来掩盖闪边。只有已复现、做过同场对照并记录代价的兼容处理，才能例外于常规同值去重。

手机顶部导航也属于共享玻璃：必须显式继承当前通透/磨砂材质，并使用与聊天/工作区相同的主题底色；不要让未传 material 的导航保留默认模糊或旧 tint。实际验收同时打开导航与聊天，比较 computed fill 和模糊参数，并目视核对文字对比和背景透光。不同位置透出的背景可以不同，玻璃自身的底色不能各用一套。

手机设置目录作为一级目的地不显示返回按钮，退出沿用品牌导航；六个分区内保留返回目录。目录采用单列的全宽六行列表，利用可用纵向空间，不改为两列卡片网格；每行的图标、文字、箭头与命中区保持同一基线。目录与分区标题行保持同高。主玻璃底边必须为首页固定底部文案与安全区留下清楚空隙，设置的保存状态只能位于玻璃内，不能压住或紧贴「让时间有引力」。内容不同由面板内部滚动承接，不得让外壳向下挤占该区域；有限尺寸动效结束后恢复稳定的内部滚动和焦点，不留下变换/高度限制，也不把动画变成常驻刷新。

**手机设置分区切换（2026-10-21）：** 从六入口目录进入任一详细分区、在详细分区间切换、以及返回目录，都是同一块设置玻璃内的内容替换，不是一次新的页面冷启动。外壳、背景取样、材质和标题基线先稳定，再让旧内容退出、新内容进入；不能出现一帧空白/透明玻璃、未完成布局的文字、边框闪亮后消失，或背景折射和磨砂在切换中短暂失效。入场、退出和高度交接沿用工作台专注的曲线与共享浮层的双向时序；不以缩放整个文字层、重新挂载背景场景或改动全页玻璃偏好来掩盖闪动。连续点入、立刻返回、快速在两个分区间切换时，动画应从当前进度交接，不能跳回首帧或留下旧分区内容。实现前必须标出目录、详细分区和返回所共用的宿主、材质来源与焦点目标；验收必须实际查看首帧、中间帧、尾帧及连续反向操作，覆盖深/浅、通透/磨砂与 320/390 px，不能以源码断言代替画面检查。

**手机顶部侧拉栏（2026-10-21）：** 顶部导航触发的侧拉栏属于临时浮层，打开和收起时固定在原导航的空间层中，不参与正文的文档流。下方当前页面的首行、滚动位置、玻璃尺寸和操作命中区必须保持原位，不能因菜单展开向下滑动、压缩、回弹或重新测量整页。菜单以任务详情同款轻遮罩和自身的入退场建立前后关系；页面仍可作为背景被看见，但不可误点。关闭时先完成菜单自身退场，再恢复焦点到原触发按钮，正文不应出现补偿性位移。只有会长期占用阅读空间的显式页面内展开内容才能改变布局；导航侧拉栏不属于该例外。验收除静态图外，必须录看打开、关闭、连续开关、已经滚动后的打开，以及键盘/触摸关闭后的正文坐标是否不变。

**后续 UI 派单与评审门槛（2026-10-21）：** 涉及手机设置、顶部导航、玻璃浮层或页面切换的任务说明，必须写出具体成熟基线、复用的组件/样式、不能改变的背景和材质状态，以及首帧/中间帧/尾帧的视觉验收项。仅写“沿用 ASTaria 风格”、通过构建、或提供最终截图，均不能视为完成；发现闪动、位移、透明度跳变、焦点错位或正文被菜单推挤时，先回到共同宿主和生命周期排查，不在单个子页叠加临时覆盖规则。

**2026-10-21 玻璃生命周期补充：** 返回首页时 `.home-scene-ui` 与 `.home-morph` 的采样祖先必须从首个可见帧保持 opacity:1。入场仅过渡文字和着色层，不能等整页淡入完成后才补上折射/磨砂。停用取样时可保留已有 SVG 定义和解码后的位移图，但不得继续订阅场景帧或编码隐藏几何；CSS fallback 仍不生成 SVG。设置主面板与特效预览 dock 只有当前可见的一方取样，不能仅靠 CSS 隐藏仍在刷新的预览玻璃。验收同时打开/收起导航、进入/返回分区，检查竖向取样分界、整片磨砂失效、首帧/退场与快速返回；正文滚动和圆角不受影响。

**2026-10-21 局部暗条复测与手机精细玻璃：** 手机SVG路径先在原生CSS执行当前磨砂半径，再用SVG做原边缘位移；SVG内部模糊为0，确保只模糊一次。通透模式不加入blur，桌面继续使用原SVG管线，Android自动及WebKit仍走原CSS路径。保持位移图、光学尺寸、折射强度、底色和当前渲染预算。

高DPI玻璃验收必须记录实际DPR、截图导出倍率，并观察原窗口中的导航开合、悬停与设置分区切换；1×隔离页或缩小JPEG未见暗条，不足以排除2×原窗口故障。重点查看控件右侧等局部暗色直线，而不只检查整片磨砂是否存在。本批用户反馈为“目前看不到暗条”，保留当次观察的边界，不写作跨设备永久解决。


### 2026-10-21 · 手机系统栏、键盘与工作区首帧

- 系统状态栏是场景的延续。Android 的 WebView、黑洞和工作区环境底色延伸到系统图标后方，不用黑／白实色栏拼接；安全区只约束交互内容，顶部、底部、横屏切口的 inset 只能应用一次。图标明暗随界面主题，不能与玻璃深浅偏好混用。
- Android 由 `ASTariaAppearancePlugin` 单独管理 edge-to-edge 与 IME insets；Capacitor `SystemBars` 保留图标风格接口，但停用其另一套 padding。Android 11+ 不提前把 WebView 缩到键盘终点，按系统动画的当前 insets 更新前景；旧版保留 compat/resize 路径。不能将 onApply 收到的动画终点当成当前帧。
- 聊天完全展开后按连续可见高度调整前景，从开始、反向到收尾共用同一公式。不得在键盘超过某个阈值时突然跳到另一套 top/height；背景 layout、相机目标、导航位置保持稳定，输入框不被键盘遮住。iOS 与浏览器保留 visualViewport 回退。
- 手机工作台、日程、余时、设置进入时，取样面及其所有祖先从首个可见帧起 opacity:1；文字、着色与边缘仍沿用现有动效。不能为入场淡化整个滚动容器，导致磨砂在动画结束才出现；退场与减少动态效果仍须保留和核对。
- 验收覆盖真实 IME 展开／收起／中途返回、横竖屏及切口、安全区、首访和返回工作区。隔离浏览器能验证前景几何和滤镜时序，但不能证明 Huawei 输入法、原生系统栏、iOS 或 GPU 已通过。


### 2026-10-22 · 安排理由、类型与背景设置

- 金色回执、工作台简报、DDL与事项集合消费同一份析熙自然说明；真实日程/事项版本变化后旧说明不得继续作为当前推荐依据。无模型说明时保留DDL、估时、已安排时长等事实，不用固定因果句补空，不在页面打开时额外请求模型。
- 依据按钮复用 `MeasuredGlassSurface` 和 `XixiBriefing`／`UpcomingDeadlines` 的26px圆形控件，触屏命中区44px，图标居中；继承通透/磨砂与深浅主题，不用独立实心金色底。集合入口与打开集合按钮为兄弟，键盘Escape收起后返回按钮；共同理由去重，分项保留关联标题，沿用 `wb-insight-reveal` 双向动画。
- 工作台开工入口依据明确的task/reminder类型、当前安排及前置工作状态；不按标题关键词猜类型，不把考试事件当复习，不仅因含due就宣称“截止更近”。只记录的工作仍是task。旧AI日期记录未分类时保留并等待语义明确，不冒充优先建议。
- 内部工具修复指令不展示为用户任务。执行提示说明具体对象、失败时段和实际影响；模型继续在工具循环内修复可修问题，只有必要取舍才向用户提问。右下角通知胶囊本轮保持不变。
- 背景模式与清晰度复用 `LocalSettings` 的Row、AdaptiveSelect，选择面板浮在原界面。实时/视频/静态图是背景选择；媒体的分辨率与码率/压缩质量独立于实时画质和帧率，媒体模式下不相关实时控件禁用。玻璃材质和已有字体不随背景模式改变。
- 视频/图像以当前黑洞横竖屏、深浅主题原生4K素材为基准，不上传用户屏幕截图；从4K生成1080p/720p。键盘不得触发竖屏素材切成横屏，按固定场景布局选素材；切换需先准备替代画面，旧画面交接完成再释放。
