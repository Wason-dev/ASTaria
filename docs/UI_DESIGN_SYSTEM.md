# ASTaria 界面与交互规范

> 状态：Beta 8 起的 UI 设计基线。面向产品设计、前端实现、代码评审和后续 AI 协作。
> 本文描述应达到的体验；文末列出的旧实现偏差不构成新界面的参考。

## 1. 如何使用本文

ASTaria 是本机优先的时间与事项工具。视觉主题是「时间有引力」：安静的宇宙场景、真实透光的玻璃、克制的金色反馈，以及可核对的具体安排。它首先是每天反复使用的工作界面，其次才是场景和动画。

做 UI 改动前，先看[当前首页截图](images/home.png)、[有回执的首页](images/home-receipt.png)、[日程周视图](images/planner.png)、[调课日视图](images/planner-day.png)、[余时](images/free-time.png)、[弦轨](images/horizon.png)、[工作台](images/workbench.png)和[工作台专注聊天](images/workbench-focus.png)，再读对应页面的实现。截图是视觉参照，不是像素模板；其中的虚构数据仅为演示。设置和首次引导暂时没有经过验收的固定截图：应在运行中的正式入口查看其当前组件及深色/浅色、通透/磨砂状态，不能凭旧版截图或单一 CSS 片段猜测。实际入口是 `src/main.tsx` 默认加载的 `BlackHolePrototype` / `HomeWorkspace`。`#/app` 指向的旧 `src/App.tsx` 不作为当前设计基线。

冲突时按下列顺序判断：

1. 用户当前明确提出的目标、行为和约束。
2. 本文对产品风格、状态和交互的要求。
3. 同一页面已经稳定使用的组件和令牌。
4. 邻近页面的可复用模式。
5. CSS 中偶然留下的字面量或旧版实现。

本文不要求一次性重构全站。改某一处时，把那一处的主题、玻璃、状态和动效做完整；不要为了“统一”顺手改动无关页面或黑洞渲染。新增视觉语言若确有必要，应先解释它为何比现有语言更适合该任务，并同步更新本文。

## 2. 核心气质

**安静但有深度。** 大场景留白，小信息精确。黑洞、地平线和折射提供空间感，控件保持轻量。页面不靠很多发光点、渐变团、悬浮装饰卡或彩色块制造“高级感”。

**透明但可读。** 玻璃要让背景可见，边缘和反射让材质成立，内容仍有稳定对比度。透明不等于消失；磨砂不等于灰白蒙版。用户选择通透或磨砂后，所有主要面板都应继承这一选择。

**有引力的连续空间。** 从首页进入工作台、日程、余时、弦轨时，用户应知道自己从哪里来、到哪里去。背景、空间位置或共享元素应有连续线索。退出是进入的逆过程，而不是突然换一张画面。

**操作优先。** 首屏直接呈现可用的任务、日历、对话或当前场景。空态简短；不把功能说明、调试提示和键盘提示长期放在界面显眼位置。真实状态、结果、撤销和失败恢复比装饰性文案重要。

**克制的个性。** 金色只负责选中、焦点、可操作边缘、少量时间提示与场景光。主要文字是暖白或深石墨色，次要信息是中性灰。红绿等语义色只在确实区分状态时少量使用，不成为页面主色。

## 3. 页面与信息架构

| 区域 | 首要任务 | 空间和密度 | 标准交互 |
| --- | --- | --- | --- |
| 首页 | 看当前、和析熙说话、核对变更 | 黑洞是第一视觉信号；周围留白；对话和当天日历同处一个空间 | 左上品牌展开一级导航；聊天展开/收拢保留上下文；回执可展开和撤销 |
| 工作台 | 从「现在可以开始」进入专注 | 比首页更密集，面板服务于扫描和执行 | 明确任务状态、步骤、截止与专注入口；返回后焦点回到合理位置 |
| 日程 | 看课程、活动、任务、真实空档 | 月/周/日视图适配宽空间；时间列对齐 | 日期和视图切换保留方向感；新建、完成和调整反馈真实保存状态 |
| 余时 | 管理持续目标、心愿和未来安排 | 宽面板与横向内容优先；目标和已排时间可对照 | 「安排」必须反映实际写入；变更可核对和撤销；堆叠内容用按钮横向浏览 |
| 弦轨 | 聚焦一天，审视日期、组和顺序 | 事件视界/地平线是空间主轴；周围控件退后 | 日期、分组、跨组移动、收拢、保存有清晰连续状态；避免每次进入无谓重新整理 |
| 设置 | 修改外观、析熙、通知、更新等 | 宽空间使用成组的两列或自适应网格；各列底边和控件宽度有秩序 | 控件保存、忙碌、失败和禁用状态可辨；外观预览不破坏当前页面 |
| 首次引导 | 完成最少量的个性化，认识主要区域 | 首页场景仍是空间背景；一片主玻璃承载短步骤 | 可跳过密钥配置；设置要明确保存；教程结束后进入真实产品 |

一级导航保持简单，子任务留在所属页面。命令入口用文字或图标加文字；局部工具按钮用清楚的图标和 tooltip。页面标题、内容左边界和首行基线保持一致：当前公共边界参考 `src/ui/workspace-heading.css` 的 `1320px` 内容最大宽度、桌面 `88px` 顶部和窄屏 `72px` 顶部。标题不是英雄文案：工作区标题约 `24px`，窄屏约 `22px`；小面板标题按信息层级缩小。

不要把全页切成一层又一层卡片。页面区块可以是无框的排列、细分隔线和留白；真正的玻璃外壳用于主区域、模态框或独立工具。重复的事项卡可以有轻薄内板，但不要在一个重玻璃卡里再叠多个重玻璃卡。

## 4. 色彩与主题

ASTaria 有正式的深色与浅色主题，且两者都支持「通透」和「柔和磨砂」。不能只验证默认深色通透。`src/xixi/preferences.ts` 保存 `theme: dark | light`、`glass: clear | soft`、`density: compact | comfortable`、卡片装饰线等偏好。当前默认是深色、通透、小巧。UI 不应在页面之间重置这些偏好。

| 语义 | 深色参考 | 浅色参考 | 用法 |
| --- | --- | --- | --- |
| 主要文字 | `#eeeae3` | `#30343a` | 标题、正文、操作名称 |
| 正文次级 | `#d4d0c9` | `#55616b` | 说明、次级内容 |
| 弱化文字 | `#bcc0c7` 附近 | `#626b75` 附近 | 时间、元信息；仍须可读 |
| 分隔线 | `#e1ded526` 附近 | `#4146501c` 至 `#41465026` | 1px 内板边线和区块划分 |
| 交互金 | `#d5bb8b` 附近 | `#927443` / `#a58752` 附近 | 选中、聚焦、可操作边缘；小面积使用 |
| 玻璃底色 | `rgb(8 10 14 / var(--glass-tint))` | `rgb(250 251 252 / var(--glass-tint))` | 透光外壳，不是整页不透明遮罩 |

这些是**语义锚点**，不是要求一次性把每个旧 hex 都替换为同一个值。新组件优先读所在页面的 `--p0-*`、`--wb-*`、`--pl-*`、`--ft-*`、`--settings-*` 等页面令牌；若缺某个语义，先在页面层补齐，再由组件读取。避免在组件深处硬编码另一套“金色”。旧全局 `:root` 中的蓝色变量来自历史界面，不应成为新 ASTaria 页面的默认强调色。

浅色不是深色加白色蒙层。浅色时同时调整文字、面板底色、边界、阴影、状态色和 `color-scheme`；去掉深色文字阴影。玻璃应有可见但轻的外投影和清晰高光，尤其在白背景上，不能看起来像消失了。强制颜色模式需要可见边界和焦点，不能仅凭透明高光表达状态。

## 5. 玻璃材质合同

### 5.1 三层结构

一个标准玻璃面板包含：

1. **取样层**：采样背后的真实场景，产生轻微模糊和边缘折射。
2. **材料层**：跟随宿主圆角的透明底色、细内高光与 1px 渐变边缘。
3. **内容层**：文字和操作位于材质之上，不被模糊，也不跟着边缘滤镜扭曲。

优先复用 `src/home/GlassSurface.tsx` 的 `MeasuredGlassSurface` / `GlassSurface`。宿主圆角必须同时约束取样、材料和内容裁切；这能避免玻璃轮廓与下方按钮或面板圆角不一致。当前 Chromium 使用 SVG backdrop 位移，其他引擎回退到 blur；不应为每个内层列表项再生成一套独立折射。`src/planner/planner-glass.css` 展示了外层真实取样、内层轻量半透明 plate 的分层方式。

玻璃的“真实性”来自背景在边缘发生细微折射、内侧有一点反光、在合适主题下有阴影；不是整片 20px 的磨砂白，也不是一圈常亮金边。反光要跟随材质，不横跨整页。悬停或键盘焦点时，金边亮起并稍微提高对比；离开后平滑回落。静止时边缘仍足够让面板被辨认。

**Windows 的材质取舍（有意为之，不是无损优化）。** `src/home/glassRendering.ts` 的 `supportsGlassRefraction` 在 Windows 上默认返回 false：Windows 走 CSS 通透/磨砂路径，保留 rim、tint、反光、悬停金边，以及通透与磨砂的差别，但不做 SVG 精细边缘位移。设置 → 外观与动画 → 玻璃渲染可以选「精细折射」换回 SVG 位移，代价是明显的帧率下降（实测数据见[渲染与后台性能](./PERFORMANCE.md)）。**这一取舍只影响玻璃边缘位移，黑洞的最高画质、渲染分辨率、采样与辉光不变**；玻璃精细度的取舍必须在设置中可见，不能把它记作同画质性能提升。滚动容器在 Windows 使用 8px 主题滚动条：透明轨道、中性圆角 thumb、悬停少量金色、无上下箭头，深浅主题都可见。

### 5.2 两种偏好

| 模式 | 目标 | 当前入口 |
| --- | --- | --- |
| 通透 `clear` | 保留场景细节，边缘折射可察觉；文字对比靠适量 tint 和局部内板保障 | 偏好映射为 `blur: 0` |
| 柔和磨砂 `soft` | 背景细节稍退后，轮廓、反光和场景仍在；不是纯不透明灰色 | 偏好映射为 `blur: 6` |

切换模式时，首页、工作台、日程、余时、弦轨相关按钮、设置和弹层的**主要玻璃外壳**都应响应。尤其检查从一个页面进入另一页面、面板打开/关闭、内容加载完成后是否突然变成纯透明或纯磨砂。内部 plate 可以为了性能使用固定的半透明材质，但它与外壳在色温、边线和明暗上应像同一种材料。

复用玻璃组件本身**不会自动继承**外观偏好：未传 `material` 的 `MeasuredGlassSurface` 会落到 `HOME_GLASS` 默认值（其中 `blur: 2`），而现有个别弹层和弦轨控件仍传固定材料。新建或调整外壳时，必须从当前偏好显式导出材质参数，并逐一检查主面板、按钮、弹层和预览是否随模式改变。不要把组件的默认材质误当成 `clear` 或 `soft` 的实现。

`HOME_GLASS` 和 `DEFAULT_APPEARANCE` 是不同使用场景的当前参数，不是覆盖全站的唯一数值表。通透度、rim、shadow、radius 等调试参数可以在既有外观系统中调节；新功能默认要继承用户偏好，而不是创建第三套隐藏的默认材质。

### 当前渲染执行约束

调整渲染、动效或后台生命周期前，先读[省电与渲染决策记录](./POWER_AND_RENDERING_DECISIONS.md)，其中列出触发条件、历史证据和回归检查。

**Beta12.1 转场时序：** 页面目的地改变不能立即触发降帧；相机弹簧仍运动时沿用保存的首页帧率（默认 60，手动 30/45/60/90/120），直到相机实际停稳才应用工作区 30 FPS 上限。输入提前就绪阈值不代表转场已结束。快速反向和恢复窗口也按真实相机状态判断，不用固定延时猜测。

帧率分区是有意的省电设计，不是缺陷：Beta12 按用户决定把工作台、余时、日程、设置的黑洞与环境渲染上限从 60 改为 **30 FPS**。首页与聊天的推荐档仍以 60 FPS 为目标，手动 30/45/60/90/120 选择继续生效，返回首页恢复所选帧率；保存的选择和独立手动画质不被改写。降低工作区背景帧率牺牲时间流畅度，不能算同画质同帧率收益，也不是对 DOM、CSS 动画或输入的全局锁帧。历史 60 FPS 策略保留在决策记录中。

重复相机快照、相同 SVG 属性与逐字节相同的位移贴图不应反复写入/编码；CSS 玻璃不创建不可见 SVG，零半径模糊使用 none。位移图按几何变化更新，静止几何不重复生成；背景仍运动时浏览器仍需合成实时 backdrop，不能宣称整个工作区 0 FPS，或已有独立的可变刷新折射控制器。隐藏工作区可在退出淡出结束后跳过布局，但必须保留编辑状态、滚动位置和快速返回行为；可见时不额外建立影响玻璃取样的 containment。测试须同时覆盖 Mac 与 Windows 的动态过程。

### 5.3 几何、层级和性能

主玻璃外壳可用较大的圆角（当前工作台、余时和设置约 `20–24px`），内板通常约 `10–16px`，密集条目约 `6–10px`；图标圆按钮才使用真正的圆。相邻边缘要共享几何逻辑，间距要相同。不要把“圆角更大”当作提高质感的通用办法。

只有少量最外层面板实时取样。滚动列表内部使用边线、轻渐变、上缘高光和浅阴影来表达材质。隐藏页面、退出中的面板和不在视口内的重玻璃应停用不必要的采样；动画尽量变换内容层的 `opacity` / `transform`，避免逐帧重新计算整块 backdrop。尊重当前 `GlassSamplingContext` 等生命周期机制。视觉测试应同时观察帧率和 GPU 占用，不能只看一帧截图。

## 6. 排版与版式

ASTaria 的文字是密集、细致而清楚的工作型排版。正式入口 `.p0` 当前使用 `Inter`, `Helvetica Neue`, `PingFang SC`, sans-serif；旧全局 `:root` 另有 `Microsoft YaHei` 等回退，不应以旧入口的字体覆盖正式界面。中英文和数字混排时要检查基线。数字时间使用 `tabular-nums`，避免时刻变化导致跳动。常见正文为 `12–13px`，辅助信息 `10–11px`；小字号只用于短元信息，长句与错误说明应比元信息更易读。不要在面板里用首页级大字，不要为了“未来感”引入难读的显示字体。

选择间距时先保持局部网格：紧凑元素常用 `4/6/8px`，普通控件与行用 `10/12px`，主区域之间用 `16/24px` 左右。这里是设计阶梯，不是每个地方必须同一个 gap；在同一行、同一列、同一组重复组件中必须一致。宽空间要利用横向比较与并列信息：设置可用两列，日程可用时间视图加侧栏，余时的多项内容优先横向分页或切换。不要在宽面板中央堆一条窄窄的竖列。

所有固定格式元素（日期格、卡片栈、工具栏、计数器、圆按钮）都要有稳定尺寸或约束，加载和 hover 不可推挤周边。长中文标题允许合理换行，长英文或路径允许 `overflow-wrap:anywhere`；只有确实为单行扫描的元信息才省略号截断，并提供可读取完整内容的途径。窄屏上先保住主要操作和文字，再让次级列重排，不允许遮挡、横向溢出或按钮文本被裁断。

## 7. 控件语言

| 目的 | 使用方式 | 不应出现 |
| --- | --- | --- |
| 明确命令 | 文本或图标加文本按钮，如保存、安排、撤销 | 把导航/工具伪装成大号营销 CTA |
| 工具动作 | 熟悉图标按钮，`aria-label` 和 tooltip 说明含义 | 用一串圆角文字胶囊代替标准图标 |
| 二元设置 | switch / checkbox | 把开关藏在模糊的“模式卡片”里 |
| 多选一 | 分段控件、tabs、select，取决于选项数量 | 为三个短选项各建一张大卡 |
| 数值调节 | slider / stepper / input，显示当前值与单位 | 只有视觉变化、没有可核对数值 |
| 颜色选择 | 色样或明确颜色名 | 用色名胶囊代替可见色样 |

按钮默认轻、边界细，hover/focus 才提高金色存在感。按下态、选中态、禁用态、忙碌态不应只靠亮度区分；必要时加入图标、位置或文字。禁用必须说明原因，或在上下文中自然可理解。相同动作在不同页面使用一致的动词。删除和撤销不是同一件事：删除需清楚标明对象和后果；已执行的安排尽可能提供本轮撤销入口。

点击目标要与视觉目标一致。圆形按钮的图标应位于**实际圆心**；hover 区域不能导致按钮消失、位移或命中断裂。鼠标、触控板、键盘都应可完成核心操作，但不要仅把横向浏览交给触控板手势；可见的前后按钮仍要存在。使用现有图标库时优先复用，保持笔画粗细一致。

## 8. 动效与空间转场

ASTaria 的动效帮助用户理解状态与位置，不是一直让界面“活着”。小控件反馈通常约 `160–260ms`，内容切换常见 `300–400ms`；跨空间的弦轨进入与退出有自己的长时序。现有模块已有不同曲线和时长，不应机械加一个全局毫秒数。设计新动效时先画出开始、经过、结束三态，再定时长。

1. **进入**：原入口仍可被识别；放大或飞行时保留共享场景、方向或材质线索。浅色模式不能在一帧内把黑色背景压重。
2. **停留**：场景运动与信息布局各司其职。黑洞和地平线是背景主角，文字、按钮、玻璃不会无故漂移或持续晃动。
3. **组内切换**：顺序、焦点、标题与光带一起连续变化；不整屏闪黑，不像跳到另一个页面。
4. **退出**：先让当前内容按层退场，再显现返回 UI 与原页面；背景亮度不能先压暗再突然变亮；文字不应比所在材质晚很多才消失。
5. **状态切换**：高度变化与内容出现协调；不突然把文字抬高。必要时使用 FLIP 或局部 GSAP，但避免为简单 hover 引入复杂时间线。

动效必须支持 `prefers-reduced-motion` 和现有用户设置。减少动态效果时保留状态区分，用短淡入或直接切换，不保留飞行、视差或晃动。动画中的控件仍需处理输入：防止重复提交、重复开启模态框、退出时点击穿透。页面隐藏、窗口恢复、渲染档位变化也要检查动画是否卡住或从错误的中间帧继续。

## 9. 反馈、析熙与真实进度

**Beta12.1 图片输入约定：** 首页与工作台「专注」共用简洁输入形态。输入框上方不放「图片」工具栏；「发给析熙」左边是带可访问名称的圆形 ＋，图标居中，继承宿主文字、分隔线和交互金。已选图片的预览、读取状态或错误提示只在对应状态下出现在输入框下方。拖图进入 ASTaria 时，优先给当前专注聊天，否则打开首页聊天，仍需主动发送。设置、弹层和忙碌状态不接受拖入，普通文字拖动保留。图片读取、换图竞争和失败不能导致误发旧附件。两处输入均需覆盖深浅色、通透/磨砂、窄屏与键盘焦点。

涉及任务、日程或目标的写操作，界面要区分「建议」「准备保存」「已经写入」「写入失败」「结果不确定」。不要把模型建议画成已经提交的安排。回执说明实际创建、修改或删除了什么，显示具体日期与时间，并提供合适的撤销。估时与已排时长不同，应并列展示，不能让旧的 30 分钟回执看起来仍代表当前 45 分钟估计。

**Beta12 回执交互约定：** 析熙正文、未完成提示和变更回执分别承担对话、执行状态和已保存事实的职责。部分失败不能用固定清单覆盖模型回复；独立提示只列「尚未完成」，沿用当前主题的细分隔线、次级文字与少量金色，不增加一层玻璃卡。排程回执标题用动作与数量，日期和起止时间只在明细列一次；保留未估时的暂定预留说明与撤销入口。模型回复中断时清楚标为系统状态，不伪造析熙的回复；模型声称完成也不能改变实际的失败或部分完成状态。

等待时显示**真实执行阶段**，例如读取、拆解、核对、搜索、排程、保存；阶段来自真实事件，不按固定时间轮播文案。能并行的读取可以并行，但状态不应夸大已完成工作。中断或断线后，先核对本机回执再显示结论；重试不应重复创建。无论进度条还是轨迹列表，都沿用玻璃、弱金和中性色，不冒出默认绿色进度样式。

空态要告诉用户当前没有什么、下一步能做什么，语气简短。错误要解释具体失败点和恢复动作。成功提示可以短暂出现，但重要操作结果不只依赖会消失的 toast。加载占位尺寸稳定，避免面板频繁伸缩。产品文字不出现示例预览、开发调试、内部工具名、系统指令或无意义的 Esc 提示。

## 10. 输入、键盘与可访问性

所有可操作元素必须有可见焦点、语义标签和一致的键盘行为。紧凑控件可以用内缩焦点环，但不能简单 `outline:none` 而没有等价替代。模态框打开后焦点进入正确位置，关闭后回到触发元素。Escape 按层退出：先取消拖动/编辑，再收拢组，最后退出弦轨；保存进行中要避免误关闭。不要为了展示“Esc”而常驻一段提示字。

纯颜色或纯光晕不是唯一状态信号；配合文字、形状、图标、选中边框或位置。`aria-pressed`、`aria-current`、`role=status`、`aria-live` 与真实状态同步。较小的视觉控件在粗指针设备上扩大命中区域，不能只放大装饰边框。深色、浅色、通透、磨砂、强制颜色、减少动态效果和键盘导航都属于正式验收矩阵。

## 11. 各页面的具体边界

**首页**：黑洞是可见的空间锚点，左上品牌导航和右侧场景不互相抢焦点。展开对话时，它与当天安排属于同一张玻璃/同一个空间，不突然变成独立重面板。变更回执和撤销必须能在真实数据状态下阅读。点击黑洞进入弦轨的命中区要稳定，不能覆盖周边按钮。

**工作台**：优先让用户知道现在可做什么、什么时候截止、如何继续。专注界面简化控件，保持析熙反馈可见；删除任务等动作应在可预期位置，不为了“极简”藏到找不到。大量事项使用可辨的堆叠和前后按钮，不能只有上下长列表。完成状态与日程、余时使用同一数据结果。

**日程**：时间刻度、课程、活动、任务与空档保持几何准确。月/周/日选择与日期切换是明确的分段和箭头控制。空档可点击区域覆盖真实时段；拖动或 hover 的发光不能改变时段位置。侧栏与聊天打开时使用真实布局轨道，不让文字躲在玻璃下面。

**余时**：持续目标的频率、预计用时、已排时长和次数可对照。目标、心愿、排程与安排情况保持同一材料家族。一个事项较多时用可见按钮左右浏览；宽屏内容充分使用横向空间。安排按钮只有实际保存后才显示成功，失败时保留上下文。浅色与磨砂模式下各面板都要有存在感。

**弦轨**：一天是一次沉浸式焦点。事件视界的圆弧与光带必须几何对齐；日期、组、事项围绕同一条地平线组织。组名默认可见，选择组、跨组移动、收拢、退出有连续动画和明确结果。背景运动服务于深度，不压过文字。组数超过一屏时前后箭头的可见圆形与命中区域同心。再次进入尽量复用仍有效的结果，不无条件重新做智能分组。智能过程展示真实动作和阶段。

**设置**：选择项少而明确，同一组控件宽度一致、列边界与底边有秩序。外观、模型、通知和更新使用同一套浅/深主题及玻璃材质。高级调试参数可在调试入口存在，不把它们全堆到日常设置。更新进度采用 ASTaria 材料与配色；「可写目录」等技术信息需翻成用户可理解的操作建议。

**首次引导**：它是一次性的任务流程，不是营销落地页。当前顺序是外观与析熙（含帧率与画质）、模型连接、首页/余时/日程/工作台/弦轨介绍。第一步给出性格强度、玻璃材质、深浅主题和帧率与画质这几项高影响设置；选择态即时可辨，继续时保存，失败则留在原步骤并说明原因。帧率与画质可选「ASTaria 推荐」（目标 60 FPS，从最高画质开始按持续负载下调并恢复）或手动分开设置，手动档保持固定。API Key 使用密码输入框，不在回显、错误提示、日志或截图中泄露；没有密钥也可「稍后配置」，不阻止进入产品。

介绍到工作台这一步时，引导必须如实反映工作台的四种状态，不能把任何一种说成另一种：读取中说明「仍在读取，也可以先继续」，读取失败说明「暂时未能读取，可在工作台重试或先继续」，读到的确是空工作台才说「现在没有可开始的事项」，有真实事项则要求打开一项再返回，并且只有真的打开并返回后才显示「已完成这一步」。这四种状态都以真实数据为准，不在引导中伪装已创建事项或已连上模型；所有步骤均可跳过；空态、加载和失败状态直接提供「继续」。整个流程使用同一块主玻璃和稳定的步骤位置；切换内容不改变外壳几何，后退保留已选内容，完成后进入真实首页。窄屏允许内容滚动，进度、主要操作和错误信息始终可找。引导的主题与玻璃选择也必须同时影响自身材质；不能预览一个外观，保存后得到另一个。

## 12. 实施流程与验收

每次新建或改动 UI，按下面顺序工作：

1. 定义页面所属区域、用户任务、主次操作和可能状态；查看对应截图与组件。
2. 先画静态布局，确认宽/窄视口的边界、文字、命中区和滚动，再接玻璃材质。
3. 让主题、通透/磨砂、密度、减少动态效果贯穿该组件及它的弹层。
4. 接真实数据和真实写入阶段；处理空、满、加载、失败、成功、撤销和重复操作。
5. 补键盘与焦点流程，再设计入场、状态切换和退场。
6. 在真实运行页面截取深色与浅色、通透与磨砂、桌面与窄屏的对照；检查动画首尾帧和中间帧，不只看最终静态图。
7. 验证性能：滚动与切换时没有成排 live backdrop 采样，没有不必要的重算或掉帧；画质不因“优化”被默默削弱。

评审时至少问：这是不是 ASTaria 当前页面的一部分？文字和操作是否先于特效？玻璃在两种材质、两种主题下是否都成立？对齐、圆角、间距、投影是否一致？hover/focus 是否清楚而不过亮？切换和退出是否连续？真实保存与可撤销结果是否可信？键盘和减少动态效果是否完整？

## 13. 现存偏差与演进方向

当前 CSS 不是一份已经完全统一的设计系统。部分页面基座默认深色，工作台部分规则基座默认浅色；`data-theme` 与根场景的 `data-night` 并行。页面强调金、弱化文字、浅色玻璃底色有多个近似值；部分旧规则硬编码透明度，可能盖过用户外观设置。`src/planner/planner-glass.css` 与布局样式有局部重复选择器。这些是后续改动要**逐处收敛**的偏差，不是新页面可以复制的自由度。

演进优先级：先保证用户四种外观组合都正确，其次让同一语义在页面间一致，再逐步收敛令牌和 CSS 来源。迁移时保留视觉回归截图与交互回归；不要为了追求单一令牌导致弦轨失去沉浸感、首页失去留白，或工作台失去可扫描性。
