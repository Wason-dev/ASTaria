# ASTaria 功能与开发说明

[返回首页](../README.md)

## 当前版本：Beta12（0.1.0-beta.12 · 预发布）

本版同时面向 macOS 13+ Apple Silicon 与 Windows x64，保留 ASTaria 的既有玻璃、主题与黑洞风格。安装包、构建来源和逐项验证见 [Beta12 说明](./RELEASE_NOTES_v0.1.0-beta.12.md)。Windows 仍是未签名试验版，当前包的实机安装、交互与自动升级/回退未验收；Windows 11 尚未测试，先前的卡顿反馈仍待复测。

- **回复与执行状态分开**：部分操作失败时保留析熙正常正文，独立提示只列「尚未完成」。已保存事实在可撤销回执中核对，排程时刻在明细出现一次；提示随消息持久化、备份和恢复，重试不会重复写入。旧版被模板覆盖的正文无法恢复。
- **完整网址直接读取**：联网搜索开关默认关闭。开启后，工具收到整条 HTTP/HTTPS 地址时由本机抓取公开 HTML 正文，绕过关键词搜索及搜索 Key 读取；普通关键词仍走 DeepSeek 搜索。拒绝本机/私网地址、带认证地址及不允许端口，每次重定向重新验证，最多 512 KiB、6,000 字符、8 秒和三次重定向。不登录、不执行页面脚本，不支持 PDF 与仅有 IPv6 的站点。只有可用正文可核对事实；搜索无正文的固定兜底仍待改进。
- **聊天图片**：首页与工作台聊天可上传一张不超过 2 MB 的 PNG、JPEG 或 WebP，发送前可移除；附件随当前模型请求传输，进入本机 SQLite、JSON 备份和重试，不进入目录同步。模型必须支持视觉输入，实际识图未验收。
- **提醒跟随安排改期**：修改时间后取消旧预约并重新建立，macOS 原生预约标识包含触发时间与内容摘要，避免旧时刻继续弹出。Windows 当前只有 App 内提醒摘要与状态，尚未支持系统弹窗和原生预约。
- **弦轨调整日期**：三日方案只重排真正改变的日期，今天已满不阻止仅修改明天的方案；仍完整校验占用、时长、锁定与截止，保存及撤销维持事务边界。相同地平线采样缓存复用，曲线公式和显示细节不变。
- **环境渲染省电**：推荐首页/聊天目标 60 FPS，手动首页/聊天 30/45/60/90/120 保留；工作台、余时、日程、设置背景最高 30 FPS，返回首页恢复所选值。画质独立，背景更新率下降会影响动效顺滑度，不能当作画质不变的加速收益。几何不变时复用玻璃位移图，CSS 背景采样仍持续；独立玻璃可变刷新率及全局静置 0 FPS 尚未实现。
- **沿用目录同步**：共享文件夹/Syncthing 的加密操作协议继续使用，每台设备独立 SQLite。新目录优化、真实 Syncthing 传送以及临时调课后自动重排全部余时仍待完成，变更回执不代表远端送达。

全量源码测试 1,531 项、回执隔离 UI 13 项已通过，测试集不重复累加。实际模型下载/推理/工具/识图、更多设备与长期功耗未验收；详细历史与当前边界见[性能记录](./PERFORMANCE.md)及[省电决策](./POWER_AND_RENDERING_DECISIONS.md)。

## BetaX 历史范围与限制（0.1.0-beta.10）

`0.1.0-beta.10`（tag `v0.1.0-beta.10`）的 GitHub 展示名称为 **BetaX**。下面是该版本已实现的能力与仍未验收的边界，**仅作为历史记录保留**；**本节的测试与安装证据属于 BetaX，不能作为 Beta11 的验证结论**。主发布为 macOS 13+ Apple Silicon（arm64）的 ad-hoc 包；同一 Release 另提供 Windows x64 试验版（`-setup.exe` 与 `-portable.zip`）。

- **Windows x64**：复用本机服务与 SQLite，数据保存在 `%APPDATA%\ASTaria`，API Key 使用系统凭据保护（DPAPI）；Release 提供 `setup.exe`（NSIS）与便携 ZIP 两个试验版资产。已在 Windows 10 x64（19044）真实交互会话核对 Electron、React、API、SQLite、WebGL2 与 DPAPI，本版合并定向测试共 123 项通过（其中 30 项是本地模型协议测试，同一批测试不重复计算），并有 Mac → Windows 10 → Mac 加密操作往返通过。最终发布 `setup.exe` 已在隔离中文路径目录真实安装，安装后交互桌面 smoke、DPAPI、原生窗口与 8 组滚动条检查通过；被占用 EXE 上的安装与卸载均以退出码 2 失败且不改动文件；卸载删除程序、快捷方式与卸载注册项并保留无关用户文件，安装测试同时证明真实 AppData 未被改动。仍未验收：Windows 11、原地升级、睡眠恢复、更广 DPI 与多屏（只测过 DPR 1.5 的一种配置）、长期功耗与 Windows 原生通知。
- **共享文件夹**：用户选择普通目录、云盘本地同步目录或 NAS 挂载目录；每台设备只写自己的加密操作文件，保留自己的本机 SQLite。界面显示目录不可用、只读、暂停、未落地、冲突和待处理原因；服务提供者只能搬运密文文件，不能把活跃 SQLite 直接共享。
- **Syncthing**：用户先自行安装并共享目录（需要 `.stfolder` 标记），再在 ASTaria 选择该目录。它与共享文件夹使用同一套操作格式、校验、解密、幂等和冲突流程；检测到 Syncthing 或目录存在不代表操作已经应用。ASTaria 不自动安装 Syncthing，也不修改防火墙或配对设置；实际跨机传送尚未验收。
- **加密操作日志**：AES-256-GCM、每设备递增序号、原子文件、事务 outbox、重复操作幂等、缺序等待和删除 tombstone。同字段离线冲突需用户确认；安排须在接收设备最新日程上重新校验，锁定安排不可静默覆盖。聊天、记忆、思考、API Key 和本地模型路径不属于同步内容。

上述能力已在源码中实现并在 macOS 与 Windows 10 x64（19044）之间做过双机往返验证；错误密钥、篡改、乱序与中断恢复的定向测试已通过。

```bash
npm install     # 安装依赖
npm run dev     # 本地开发服务器
npm run build   # 类型检查 + 生产构建（输出到 dist/）
npm run build:preview # 设计预览构建（不注册新的离线缓存）
```

外观统一从「设置 → 外观与动画」调整。专注与休息时长在所有构建中均可调整。

## 析熙与本机数据

从源码开发需要 Node.js 24.19 或更新的 Node 24 版本（使用内置 `node:sqlite`）；macOS 还需要 Command Line Tools。开发和本地预览服务都提供同源 `/api`，请保持服务运行；单独打开 `dist/index.html` 或把静态文件托管到远程并不包含本机服务。桌面包需要同时包含页面、本机服务和预编译的凭据助手，不能只把网页套进窗口。在浏览器里运行源码不提供 DPAPI 和文件夹同步，这两项需要运行 Electron 桌面包。

```bash
npm run dev -- --host 127.0.0.1 --port 5177
# 或构建后预览
npm run build:preview
npm run preview -- --host 127.0.0.1 --port 5188
```

在左上角 ASTaria → 设置中输入 DeepSeek API Key，选择「保存密钥」，再「测试连接」。密钥通过本机私有管道写入系统凭据存储：macOS 为钥匙串，条目为 `dev.wason.ASTaria.deepseek / api-key`；Windows 为系统凭据保护（DPAPI）。不写入 `.env`、Git、SQLite、浏览器存储，也不向前端回显。服务固定请求 DeepSeek 官方 HTTPS 地址。macOS 源码开发时每次启动首次使用会在临时私有目录编译本机凭据助手，执行前校验完整性，桌面包已包含预编译助手；系统可能请求凭据访问授权。测试连接会产生少量 API 用量。

也可以在「设置 → 析熙 → 连接模型」切换到本地模型。支持本机 Ollama、LM Studio 和 OpenAI 兼容服务；地址只接受 `127.0.0.1`、`localhost` 或 `[::1]`，可读取已加载模型，也可手写模型名。连接地址与设备详细信息默认收起。保存后用「测试连接与工具」执行一次工具调用往返检查；没有通过工具调用的模型只适合普通问答，不应承担修改任务或日程。设备建议按系统内存估算，不测推理速度，也不会在本地失败时偷偷切回云端。首次切换本地会按设备内存预选 Qwen3 4B / 8B / 14B / 32B，已保存的自定义模型不被替换；未确认安装的推荐型号不会自动变成可用连接。本地建议至少 32K 上下文，仍可选择其他支持工具调用的模型。

Ollama 用户可展开「还没有模型？帮我安装」，从 Qwen3 4B / 8B / 14B / 32B 中选择。下载前展示预计下载量、磁盘需求与内存建议，确认后由本机 Ollama 下载，支持进度、取消与重新打开设置查看；完成后再次读取已安装列表，核对成功才允许选用。下载不会自动切换当前模型。取消可能保留 Ollama 的下载缓存；ASTaria 服务重启后需重新检测，已安装文件仍由 Ollama 管理。尚未安装 Ollama 时提供官方下载入口，需要用户安装并打开运行时；LM Studio 与其他兼容服务仍由其自身管理模型下载。回归测试使用模拟服务，不会真实下载模型。

设置中的默认模型可选择 DeepSeek Flash 或 DeepSeek V4 Pro，初始为 Flash，选择保存在本机数据库并跨浏览器共享。思考深度默认 Low，可选 High、Max 或关闭；析熙个性默认「中」，已有用户设置不会被覆盖。思考设置直接传给 DeepSeek，工具调用轮次会原样保留模型返回的 reasoning_content。聊天按 Enter 发送、Shift+Enter 换行，中文输入法确认候选字不会误发；自己的消息即时显示，失败后可重试。析熙可以提出带快捷选项的问题，也支持自由输入回答。消息可复制，自己的消息可撤回；撤回后停止该轮后续处理并排除相关上下文，已执行的事项变更仍可从回执单独撤销。

联网搜索位于同一连接设置中，默认关闭，且本地模型模式不会默认打开。用户明确开启后，析熙才会收到 `web_search` 工具；搜索请求固定使用 DeepSeek Anthropic 原生 `web_search_20250305`，只发送查询词，不附带本机课表、任务、聊天、记忆或 API Key。返回结果只保留标题、链接、摘要和发布时间，网页内容视为不可信资料，网页里的指令不会改变 ASTaria 权限，也不会自动写入事项、日历或记忆。搜索失败、限流、无结果和取消会以真实错误结束，不伪造来源。开启联网搜索后，每条来源都会抓取网页正文并标记为抓取成功、抓取失败或正文为空；只有成功取得正文的来源可用于核对事实或日期，没有可核实正文时逐条列出核验状态与抓取时间。其他搜索 provider 尚未接入。

「流式输出」默认开启，可在同一连接设置中关闭。思考过程与回复逐步显示，思考区可折叠；这些是模型实际返回的内容，本地模型是否返回思考字段取决于服务。生成中的文字不代替执行回执，最终以已保存状态为准。网络中断保留原请求 ID 和已保存进度，重试不会重复执行已完成的操作。开关从下一条消息生效，不改变正在执行的请求。

黑洞帧率位于「设置 → 外观与动画」：120、90、60、45、30 FPS。帧率与手动画质独立，降低帧率不会自动降低已选的画质。Beta12 按省电设计分区生效：**首页与聊天沿用所选帧率；工作区的黑洞与环境渲染最高 30 FPS**，返回首页恢复所选帧率。画质独立，工作区背景动效的更新频率下降属于明确取舍。此上限不锁定 DOM、输入或显示器刷新率。实际帧率受显示器刷新率与设备性能限制，页面隐藏时渲染会自动暂停；测试浏览器应在验证结束后退出，避免后台残留持续消耗 GPU。

「帧率与画质」把帧率和黑洞画质拆成两项独立设置：帧率可选 30 / 45 / 60 / 90 / 120 FPS，画质可选最高、高、轻量、兼容（以及默认的「ASTaria 推荐 · 自动」）。选择手动画质后帧率才可独立调整；手动画质保持固定，不再随负载变化。推荐档首页目标 60 FPS、工作区上限 30 FPS，从最高画质开始，持续卡顿时自动下调，流畅后逐步恢复。工作区帧率上限本身不会连带降低画质。玻璃渲染另有独立选项：默认「自动」（Windows 优先流畅玻璃），可手动切到「精细折射」；后者仍可能有较高开销。

数据存放于系统数据目录下的 `astaria.sqlite`：macOS 为 `~/Library/Application Support/ASTaria/`（目录权限 0700、数据库 0600），Windows 为 `%APPDATA%\ASTaria`。同一系统用户下的浏览器共用此文件。SQLite 保存任务、分类、日历、安排、对话、记忆、摘要、变更回执、推演、接力和正式设置；默认专注与休息时长保存在本机设置中，并随备份导出与恢复；正在进行的倒计时进度与开发调参仍保存在浏览器中。旧浏览器业务数据首次打开后幂等迁移，源数据保留，旧 API 设置不会导入。若曾在旧界面保存过 API Key，请在迁入钥匙串后清理旧的 `astaria-settings` 浏览器数据库，并按需在 DeepSeek 控制台轮换旧密钥。

析熙可读取和拆分事项、设置截止与计划时间、修改状态、记住有原话来源的偏好。每次修改有回执，可以撤销；之后被手动改过的记录会保护性拒绝覆盖。临时记忆带有效期，任务记忆只用于相关任务。设置中可查看来源或忘记；相关来源及衍生上下文会被排除，原始聊天仍供回看。长期聊天使用有来源的摘要加最近完整轮次，并按需检索旧对话。

「设置 → 析熙」可调整个性强度：低（简洁温和）、中（自然俏皮）、高（有主见，嘴硬一点，做事认真），默认「中」。高档只在轻松语境里偶尔顶一句，关心落在具体回应和行动上；用户难过、着急或纠错时收起打趣。保存后从下一条回复开始生效，不必新开对话；各档只调整表达，与主动权限、提醒频率、记忆开关独立。设置随本机数据持久化并进入备份。

人格底色位于 `server/prompts/persona.md`，三档表达由 `server/personality.mjs` 按当前设置选取，工作与工具协议位于 `server/prompts/working.md`。请求时按需选取对话、记忆、任务与日程资料交给 DeepSeek。测试使用虚拟 provider 和临时数据库，不需要真实密钥或付费请求。

上下文在每次实际请求前统一计算预算，包含实时钟表、工具定义和待完成事项。较长的旧对话与工具结果只压缩发送副本，原文保留在本机；省略的读取明确标记为未读全，不能当成空闲。多项明确时段分别核验；已保存的操作和未完成部分分别可核对，重试接续原请求。全部已核验的排程即使最后文字回复超限，也可用本地回执确认，不重复执行。

**Beta12 回执交互：** 部分操作失败不再用固定成功清单覆盖正常回复，「尚未完成」作为独立状态提示列出具体原因。已保存的结果只放在可撤销回执中；排程卡片标题不重复整组日期和时刻，具体时段在明细列一次。未知估时的暂定预留说明仍保留。模型回复中断且操作已全部核验时，显示独立系统提示及回执；重试不会重复提交已保存操作。提示随消息保存并进入备份，撤回对话时隐藏提示，实际写入仍须单独撤销。旧版已被模板替换的历史正文无法由此恢复；旧排程卡片的重复标题可在读取时简化。

析熙新建事项后会直接根据真实空档安排日历，不再先问是否安排。按已有估时分配；未给用时时先预留 30 分钟，并注明可修改。安排避开课程、休息、已有任务和锁定时段，遵守明确日期、可用窗口及截止时间；空档不足会列出剩余未安排部分。“只记录、先不安排”和设置中的“先提出方案”仍会保留原日程。任务和本次自动安排在同一事务提交，撤销创建也会撤销关联的自动时段；后续手动修改仍受版本保护。

重复任务由一个 repeat 模板按目标日期展开，每个日期独立记录进度，只在当天安排一段完整时长；可优先放到指定窗口的末尾，不把多天任务挤到同一天，也不拆成零碎时段。空档不足会列出未排日期。创建和初次安排合并为一个公开回执，可一起撤销。

工作台「现在可以开始」以真实日程块判断：没有具体时间的事项可直接开始；有具体安排的事项在开始前 20 分钟才进入。已过时段但尚未完成的事项会标注可继续。无明确截止的列表默认折叠；已完成默认只显示最近 7 天并分页，完整历史支持搜索与日期筛选。

指定钟点的新事项可通过 `create_tasks` 的每项 `schedule` 与 `expectedRevision`，在读取日程后把事项和时段一起保存；冲突时一起回滚。兼容分步创建的调用，每项日历义务独立核验：移动考试成功不能代替社团活动入历，明确日期和时段按实际记录检查。未完成时继续执行，失败保留重试，撤销后的安排不会自动复活。默认日程上下文将“晚自习”等窗口与占用者、实际剩余时间一起提供；后续日程和截断计数保持可辨，全天占用分钟数不代表某个任务的用时。

聊天的创建事项回执下方只保留 DDL 和预估时间快捷设置。预估时间支持 15 / 20 / 30 / 45 / 60 分钟、自定义和清除，修改只更新任务估时，不会偷偷伸缩已有日程。DDL 提供「今天／明天／后天／日期与时刻」，直接修改原事项的 DDL；可快捷选择 08:00、12:00、18:00、20:00 或全天，也能自定义分钟和清除日期，不需要再次聊天或重新创建。更新同步工作台与日程；若新 DDL 早于已有时段，会提示调整计划。每轮工作单分别记录工具提交、未完成部分和回复状态；已提交的完整操作遇到回复生成失败时，会用本地事实回执收口。

## 日程与安排

每周安排总览可筛选单周/双周，保存共用第1周周一统一后续规则；已存在的单日快照和任务时段保留。普通任务初排优先找完整时段，确需拆分时每段至少15分钟，明确短任务可完整安排。预计时长与已排分钟分开显示，修改估时不会自动扩张已保存时段。

从左上角 ASTaria 进入「日程」。月视图观察截止日期与忙闲分布，周视图显示课程、固定活动、休息、空课与任务时段，日视图展开一天的完整时间线。月／周／日切换保留选中的日期，并展示对应日期的可支配时间与出门准备。任务的截止日期和安排时段分别保存，移除时段会保留任务。旧启动设置中的日历、时间表自动映射到日程。

导航始终向右展开，窄屏可在栏内横向滚动，也可用方向键、Home／End 导航。日程页面将当天信息集中在顶部横向概览，下方主视图使用整行宽度；需要与析熙对话时可返回首页。时间表中的空课用金色边框表示，点击整块或按 Enter／空格即可编辑。临时调课日也可点击课程、休息或空课编辑来源的每周安排，窗口会说明影响范围；保存后同步今天和未来的相关调课日，历史记录保持不变。来源已被移除时保留历史只读内容，并提供当前每周安排入口。

日程按内容完整展开，统一滚动整个页面查看下方日期与晚间时段，主玻璃板内部不再上下滚动。窄屏的周视图保留横向滚动；日视图使用单列时间线。

首次使用默认加入周一至周五 18:00–20:00 晚自习，可自行修改，也可自己录入课程、空课与时间。未记录的空白不计为空闲，可支配时间只统计明确的空课或自习，并扣除固定活动、休息及已安排任务。核对完成后可点击「已核对完成」，之后仍可编辑每周安排。每周安排可选择每周、单周或双周，并明确指定第 1 周的周一；周次跨年连续计算。单日调课使用目标日期所在周的课表，历史快照保持原样。旧课表默认为每周。

点击课程可记录地点及所需物品；点击任务可填写准备说明、携带物品、是否需要提交，并添加或锁定时段。出门清单会汇总当日需要的物品，保留来源及「建议」标记。完成任务与确认提交是独立状态：已经做完但还没提交的事项仍会提醒，实际提交由用户确认，也可撤回确认。

任务指定钟点或修改现有计划时，析熙通过 `read_planner` 读取目标日期起最多 7 天的安排，再用 `plan_tasks` 保存时段。任务排程会检查日期版本、时区、过去时间、重叠、DDL 和锁定状态；未知空档需先确认，锁定时段需用户在页面解锁。AI 的 `startAt` 仅表示日期意向，精确钟点由排程工具处理。多个任务顺延可同批提交，按最终布局检查冲突并原子保存，可整体撤销；排程回执返回实际保存的时段。`remove_plan` 移除未锁定时段，`save_task_preparation` 保存明确的准备信息，操作均提供可查看、可撤销的回执。

已确定日期和钟点的会议、校庆、临时课程等作为单日活动保存，独立于任务与每周课表。析熙读取目标日后通过 `save_day_events` 一次记录多项活动；活动可以跨越可用时段边界，已有重叠会明确返回，不会覆盖原计划或改动每周模板。首页与日程都显示活动并支持直接编辑。保存、删除、重试与撤销使用版本校验和工作单核验，完成回复以当前实际记录为准。未能写入时如实说明失败，不再反复注入相互矛盾的强制排程指令。

站内可见页面会根据未读变更、真实空闲和准备清单显示通知。在 macOS App 的「设置 → 通知」可另外开启系统提醒：课程、单日活动和已安排事项提前 5 分钟，明确时刻的 DDL 提前 30 分钟，仅日期的 DDL 当天 20:00。提醒遵循免打扰时段，已过提醒时刻不补发。

系统提醒默认关闭，需允许「ASTaria 提醒」发送通知。未来 30 天内最近的 64 条预约交给 macOS，关闭窗口或退出 App 后仍可触发；修改、完成、删除后会更新预约，关闭开关会取消。打开 App、恢复使用和运行期间的定期同步补充后续提醒，长期不打开时不会超出这批预约继续生成。系统权限、专注模式和关机影响送达。定位、设备感知和析熙立绘尚未接入。

## 余时、弦轨与接力

余时顶部的“聊聊一个心愿”可在尚无心愿时发起澄清，先保存想法，明确选择加入自动安排后才占用日程。

从左上角 ASTaria →「余时」管理持续学习目标。可设置优先级、每周最低频率、单次时长偏好和阶段目标，默认单次20–40分钟，可自行调整。每个目标只关联一个长期事项；日历保存具体学习时段。新目标保存后安排未来七天，之后每天首次打开应用补充安排，按实际空档分散到不同日期、避开现有事项并留出休息。暂停不再新增安排；频率无法满足会显示缺口。过去的安排不算完成，用户逐段记录完成、学习反馈和下次接着做的内容。撤销排程保留目标且当日自动补排不会复活已撤销的时段。

析熙可通过 `read_free_time` 读取目标、时段与反馈，使用 `save_free_time_goal` 调整重点、频率和时长，通过 `schedule_free_time` 补排，并用 `complete_free_time_session` 记录某次学习完成而不结束长期目标。旧牵挂和合适时机并入余时的待考虑区域，显式加入后才成为自动安排的目标。

点击首页右侧黑洞或余时的「弦轨」入口，镜头靠近事件视界边缘，停在一条有厚度与流动纹理的地平线上。今天、明天、后天逐日查看，组名常驻；点开组后，事项沿同一条地平线展开。「收拢这组」回到组视图，退出沿原路回拉。弦轨外观统一在「设置 → 外观与动画」调整，场景内不再放开发调试入口。

弦轨读取这三天内**已经安排但尚未完成的真实任务段**。今天原定时间已过、仍待办的事项也会显示，标记为待重新安排；真正处于进行中且已经开始的事项、锁定段保留在固定安排中。未排进日历的待办不会自动加入轨道。

首次进入尚未保存分组的日程，先显示本地按目标和分类整理的初稿，再由当前模型按实际内容与共同目标智能分组。不同日期分开，每组最多 6 段；不因同一学科或都属于生活事务就硬凑。智能建议只改草稿，日程未变时两分钟内复用结果。已保存的分组会保留，想重整时可点「智能整理」。模型失败会说明原因，仍可使用原分组手动调整。

拖动组调整当天顺序，拖到顶部日期可整组换天；展开后可以调整组内顺序。键盘方向键也可排序，Alt 加方向键换天。「调整分组」支持改名、拆出事项、合组和跨组移动；手动调整后先完成保存，避免智能建议覆盖草稿。重复事项遵守原日期，其他事项仍受 DDL 和余时目标日期约束。组再多也会分页完整保留。

分组编辑使用单片玻璃和行分隔，继承全局通透／磨砂设置。打开时后方文字淡出、光带降低亮度，黑洞场景仍然保留；返回弦轨时恢复。

点击「完成」才提交草稿。三日弦轨先在本地检查真实空档、连续用时和截止时间，生成符合所选日期、组序和组内顺序的初排，再由当前所选模型用一次请求微调具体时刻。只发送必要的排程信息，模型只返回需要改变的起点；云端智能分组和排程的思考深度最高为 low，不更改聊天设置，本地模型仍使用当前连接。进度贴合地平线，显示实际读到的事项数量、每天的用时与空档、模型返回的具体建议、终检和保存；可展开活动记录，并显示已等待时间，不展示内部推理或虚构工具调用。

模型返回后重新核对日程版本、固定占用和全部约束，全部通过才整批保存，分组随日程一起持久化，保留原任务段与完整时长，并提供撤销回执。仅改名或同布局分组标识变化时保留原时间，无需模型排程；未改动、重复完成和明显无解的草稿也无需再次调用模型。今天有待重新安排的过时段时，即使未拖动也会执行排程。如果等待模型期间合法初排起点刚过去，会按当前空档更新并再次完整校验；真实日程变化仍须重新读取。模型超时、失败或校验失败均保留原日程，不静默回退或写入部分安排。一次提交目前最多调整 128 个可移动任务段；七日普通弦轨保留原模型排程路径。

专注页按计时、任务步骤、析熙聊天排列。在右侧聊天粘贴作业要求，析熙可以把当前任务拆成可勾选的步骤，保留每一步的材料与提交要求。中间清单显示完成数量、进度和下一步，较长清单分页查看。勾选或取消勾选后立即存入本机数据库，再次进入、刷新或换浏览器都会恢复；重新拆分保留已有进度。明确给出当前任务的具体明细时，析熙直接保存对应步骤，条目数量与顺序按用户提供的内容保留。全部勾选不会自动完成整项任务或确认提交。析熙写入步骤有可撤销回执，后续手动勾选会保护进度，阻止旧回执覆盖。

左侧玻璃板在专注和接力之间切换，中间始终保留任务步骤。点击与专注按钮并排的金色药丸「留个接力」会暂停计时，在同一面板记录进度、卡点、下一步和材料；保存后回到计时界面并显示接力摘要，继续计时由用户决定。返回专注会保留未保存草稿，已保存的记录下次进入可恢复。切换只移动玻璃内部内容，玻璃本身保持不动。接力与牵挂保留原话来源和版本，AI来源撤回时衍生记录退出上下文。

余时中的待考虑清单保存尚未成为任务的愿望，可编辑、暂停、恢复、移除或设置有效期。机会提示依据真实空闲，所需物品及其他条件仍需用户确认；未提供用时时暂按30分钟试留并注明估计。它不会自动创建任务或占用日程。点「聊清楚」可在原有析熙对话里逐步明确动机、第一小步和条件；确认后的补充写回同一份心愿。澄清草稿与普通聊天草稿分别保留。明确选择加入余时后才成为自动安排的目标，原心愿暂停留意，避免重复推荐。

## 设置与黑洞回应

设置使用独立页面，分为通用、析熙、时间安排、通知、外观与动画、数据。「析熙」统一管理模型连接、个性、主动程度与记忆；记忆明细默认收起，可翻页查看来源、更正或忘记。通知页左侧为提醒设置，右侧为变更记录，可按全部、未读、已读、已撤销筛选；每页四条，详情按需展开，撤销在对应记录右上角。其他设置包括启动页面、默认专注休息、排程缓冲、晚自习和周末可安排时段、免打扰、网格、玻璃预设和信息密度。数据页提供无 API Key 的 JSON 备份和显式确认恢复，恢复会使旧方案及旧操作快照失效。

「外观与动画 → 玻璃与空间 → 卡片装饰线」提供左右对称、仅左侧、隐藏，默认左右对称。课程、安排和同类小卡片沿用各自状态色，金色可安排框和选中轮廓保留；设置保存在本机数据库并跨浏览器共享。

「外观与动画」提供光潮、弦光、引星、关闭，以及轻柔/标准/鲜明强度和减弱动态。默认光潮·轻柔。「思考时显示数字」独立控制黑洞内部的数据流：小号、竖直排列的 0 与 1 持续下落，采用接近黑色的中性灰与轻微景深层次，不再金色闪烁；数字限制在黑洞轮廓内，边缘平滑淡出。只在析熙思考时出现，开始回复后继续下落并在约 1.2 秒内淡出，减少动态时缩短变化。该层沿用原黑洞渲染和后期管线，不额外建立全屏渲染链。

预览时收起设置内容以展示黑洞，返回时通过退场动画恢复原滚动位置与焦点，退场同时释放玻璃折射和阴影。预览不调用模型；实际聊天由思考、执行与回复状态驱动视觉。关闭盘面回应与关闭思考数字是两个独立选择。外观设置保留必要的样式、强度、数字开关和动态选项，底层兼容参数不全部暴露为调试控件。

模型偶尔将提问工具输出为 DSML 文本时，服务会将完整的单个提问恢复为问题与快捷选项。截断、混合或未知的协议内容会显示可读错误，不执行文本中的写操作；旧消息读取时也会修正显示，保留原始存储。

上下文组装优先保留当前请求和相邻四轮对话，再分配次要资料的空间。历史工具负载转换为精简操作记录，保留任务 ID 与问题选项；较长原文保留检索来源，撤回、忘记和关闭历史使用的边界继续生效。

- **相机采样去重**：界面几何只在相机真正推进时更新，环境模拟时钟不触发重算；过渡结束、暂停与减少动态各自仍触发一次。
- **聊天输入响应**：聊天到达原定可输入位置后，输入与焦点不再额外等待相机完全停稳；收拢、反转和切页继续保留草稿与合理焦点。Mac 原生对照消除约 1.1 秒额外等待，Windows 独立验证待完成；动画和画质保持原值。
- **切页保留渲染调度**：有效帧率预算与画质未变时，切换页面不再重建渲染档位。
- **位移贴图复用**：同尺寸下半径变化若产生逐字节相同的 RGBA，则复用已有 PNG 不再编码；参数与像素公式未变。
- **边界条件**：浅色精确端点不再计算贡献为零的辉光中间通道；光标强度恰为 0 时跳过无效光学运算；所有非零特效强度保持完整。RAF 抖动容差由 0.25ms 放宽到 2ms，绝对 deadline 仍按完整间隔推进，目标平均 FPS 不变。
- **帧率分区按省电设计生效**：手动选择的 90 / 120 FPS 在首页与聊天沿用；工作区的黑洞与环境渲染最高 60 FPS（这是有意的省电上限，不是缺陷）；30 / 45 档不会被升档，画质独立、不随帧率上限下调，返回首页即恢复所选帧率。本版保留该上限，只修复高刷时间戳抖动造成的误跳帧。

**验收状态**：旧本地包已完成两端独立安装/启动验收，冻结时源码测试 1,494 项、Windows 专项 63 项、浏览器帧率设置专项 52 项通过；两端各完成 40 项交互、16 组 GPU 参考、12 张布局截图与保留页面检查。Windows 切页与展开聊天仍存在卡顿，体验验收未通过。2026-10-06 当前源码测试 1,508 项通过，Mac 本轮聊天修复的 20 项动态矩阵与六组真实输入检查通过；Windows 修复实测与空闲性能复测仍待完成。构建来源和安装/启动/卸载结果见 [Beta11 说明](./RELEASE_NOTES_v0.1.0-beta.11.md)，性能数字见[性能记录](./PERFORMANCE.md)。

Windows 首次展开聊天仍有偶发长帧，手动精细折射仍高开销；Windows 11、更多 GPU/DPI/多屏、休眠恢复、长期功耗、真实模型下载与 Syncthing 实际跨机传送未验收。旧综合浏览器预览脚本未整体迁移，详见[交接边界](./BETA11_HANDOFF.md#开发验收脚本边界)。

`0.1.0-beta.10`（tag `v0.1.0-beta.10`）在 GitHub 的展示名称为 **BetaX**。主发布面向 macOS 13+ Apple Silicon（arm64），使用 ad-hoc 签名，未做 Apple 公证。桌面运行时采用 Electron 44.1.0，内含 Node 本机服务、预编译的凭据助手和系统提醒助手。构建机需要 Apple Silicon Mac、arm64 Node.js 24.19+（Node 24 系列）、Command Line Tools 和独立取得的干净 Electron.app 及其 LICENSE、LICENSES.chromium.html；应用运行时不应依赖开发服务器或系统 Node。安装步骤以[安装说明](./INSTALL.md)为准。

### macOS 打包与产物路径

```bash
npm ci
npm run build:desktop
node scripts/third-party-notices.mjs
npm run package:desktop -- --runtime /path/to/Electron.app --out desktop-builds/0.1.0-beta.10
node scripts/package-dmg.mjs --app desktop-builds/0.1.0-beta.10/ASTaria-0.1.0-beta.10-mac-arm64/ASTaria.app --out desktop-builds/0.1.0-beta.10/release --instructions docs/INSTALL.md --sign-manifest /private/path/update-ed25519.pem
```

两条命令沿用统一命名格式：`--out` 指向版本子目录后，打包器写入 `desktop-builds/0.1.0-beta.10/ASTaria-0.1.0-beta.10-mac-arm64/`（App、ZIP、SHA-256、构建清单），DMG 命令写入同版本 `desktop-builds/0.1.0-beta.10/release/`（`ASTaria-0.1.0-beta.10-mac-arm64-adhoc.dmg`、`.dmg.sha256`、`.manifest.json`、小写 `install.txt`）。打包器拒绝覆盖同版本产物，只复制指定源码和构建文件，编译并随包放入凭据及提醒助手、Electron/Chromium 许可、GSAP 许可和[第三方依赖许可清单](../THIRD_PARTY_NOTICES.txt)，然后完成 ad-hoc 签名、压缩和 SHA-256 清单。`--runtime` 必须指向 arm64 Electron.app，Electron 的两份许可文件须与它同目录。打包不包含个人数据库、密钥、环境文件或测试日志。本机开发产物留在被 Git 忽略的 `desktop-builds/`。

DMG 根目录只有 App、指向 `/Applications` 的 Applications 快捷方式和安装说明；用户自己把 App 拖入 Applications，打包脚本不会复制进 `/Applications`。版本 Release 的说明书资产名为小写 `install.txt`，内容就是 `--instructions` 指定的 `docs/INSTALL.md`（仓库内 `INSTALL.md` 与 `install.txt` 是同一份正文的副本）。DMG 不含开发者的课表、事项、析熙聊天、记忆、数据库或备份。App 和 DMG 均为 ad-hoc 签名、未公证；若被 macOS 拦截，先核对来源和校验值，优先使用「系统设置 → 隐私与安全性 → 仍要打开」。[安装说明](./INSTALL.md) 另附只针对此 App 的终端命令。应用使用层叠三瓣 SVG 图标及透明顶部拖动区；图标生成方法见 [图标说明](../design/icon-vector/README.md)。

「设置 → 通用 → App 更新」支持检查 GitHub 发布、查看更新说明及下载匹配芯片架构的 DMG。自动检查默认开启，App 可见时最多每六小时检查一次，也可关闭或手动检查；遇到 GitHub 限流会退避，不反复请求。检查仅读取公开版本信息，不发送课表、聊天或模型密钥。Beta 安装可接收后续 beta 和正式版，正式版只接收正式发布。同版本替换包通过更晚的 App 构建时间和不同源码提交识别，编辑 Release 说明不会触发更新。

「下载并校验」完成后可选择「安装并重启」；下载支持取消，安装前核对 SHA-256、包大小、App 身份、架构、构建记录、代码签名和发布清单的 Ed25519 签名，原应用在新版本启动成功前保留，失败会尝试回退。本机数据不随 App 替换。App 必须位于可写目录；直接从 DMG 或受系统隔离的临时路径运行时，请先复制安装。发布须同时上传匹配的 DMG 和构建清单。

Windows x64 标准安装版同样接入应用内更新：只有运行中的 EXE 位于 `%LOCALAPPDATA%\Programs\ASTaria\ASTaria.exe` 时才能安装；可手动检查更新，自动检查默认开启、App 可见时最多每六小时一次且可关闭；下载后按发布清单核对大小与 SHA-256，验签通过才成为安装候选，退出 App 后由静默安装脚本安装并重启新版本；新版本未通过启动确认时会把旧版本移回并尝试重启。便携版或非标准安装位置不提供应用内安装，界面提示退出 App 后手动运行安装包。Windows 更新同样不覆盖 `%APPDATA%\ASTaria` 用户数据；Release 清单的 Ed25519 验签与 Windows 包代码签名是两件事，Windows 包仍是未签名试验包。Windows 应用内更新是在旧 Beta11 本地包（构建源码 `da3a1c1`）冻结之后加入源码的，不在该包内，尚未在真实 Windows 上验收。

备份导出与恢复使用格式化 JSON 的 32 MiB UTF-8 字节上限，超限明确拒绝且不改动本机数据，不导出无法恢复的超限文件。中文字节、精确上限、超限拒绝与失败原子性测试已通过。恢复会更新状态，之后的新备份仍会重新核验大小。macOS 桌面端数据位于 `~/Library/Application Support/ASTaria/`：首次运行前应从「设置 → 数据」导出备份并保留原备份文件；浏览器保存的专注计时、外观调参等状态不等同于 SQLite 数据，不应假定会自动复制进桌面容器。若使用本地模型，Ollama 或 LM Studio 仍需在本机运行。性能数字见[性能说明](./PERFORMANCE.md)；干净机器、休眠恢复与长期功耗仍需继续测试。

### Windows x64 试验版（随 GitHub Release 提供）

`scripts/package-windows.mjs` 产出 `ASTaria-0.1.0-beta.10-win-x64/`，Release 上传 `ASTaria-0.1.0-beta.10-win-x64-setup.exe`（NSIS 安装程序）与 `ASTaria-0.1.0-beta.10-win-x64-portable.zip`：需要自行准备解压好的 Electron win32-x64 运行时；NSIS 需要额外提供 `makensis` 才编译，未提供时只生成 `.nsi` 与便携 ZIP。已核对：Windows 10 x64（19044）真实交互会话中的 Electron 启动、React 界面、本机 API、SQLite、WebGL2 与 DPAPI 凭据保护；本版合并定向测试共 123 项通过，其中包含 30 项本地模型协议测试（同批测试，不重复计算）；Mac → Windows 10 → Mac 的中文任务、假期与完成状态加密操作往返通过。安装与卸载已用最终发布 `setup.exe` 在隔离中文路径目录实测：安装成功，安装后交互桌面 smoke、DPAPI、原生窗口与 8 组滚动条检查通过；被占用 EXE 上的安装与卸载均退出码 2 且未修改文件；卸载删除程序、快捷方式与卸载注册项，保留无关用户文件，且安装测试证明真实 AppData 未变。仍未验收：Windows 11、原地升级、睡眠恢复、更广 DPI 与多屏（仅 DPR 1.5 的一种配置）、长期功耗与 Windows 原生通知。两个资产都是试验版，不作为正式 Windows 发行版。

以上 123 项合并定向测试与安装/卸载验收属于 BetaX（`0.1.0-beta.10`）时点的 Windows x64 试验版。旧 Beta11 本地测试包（构建源码 `da3a1c1`）同样不含 Windows 应用内更新：该功能是在本地包冻结之后才加入源码的，已有自动化测试，但尚未在真实 Windows 上验收。

Windows 本地模型复用回环 HTTP 协议：需用户先安装并打开 Ollama，ASTaria 才能请求下载受支持模型；也可连接已有兼容服务。上述 30 项本地模型协议测试已计入本版 123 项合并定向测试，不另外累加；本地模型的实际下载、GPU/CPU 推理与工具调用尚未完成验证。

Windows 数据保存在 `%APPDATA%\ASTaria`。ZIP 需要整体解压后运行 `ASTaria.exe`，数据不随 EXE 移动；便携版更新时退出 App、导出备份，再把新包解压到新目录。BetaX 时点的 Windows 试验版没有应用内更新，也没有退出 App 后的提醒（历史边界）；当前源码中 Windows x64 标准安装版已接入应用内更新，便携版或非标准安装位置仍只能手动运行安装包。该能力尚未实机验收：Windows 10 的真实自动升级与失败回退未验收，Windows 11 未验收。在浏览器里运行源码不提供 DPAPI 和文件夹同步，这两项需要运行 Electron 包。

#### Windows 窗口外壳与滚动条

Windows 版不使用独立的应用菜单，也不使用系统原生标题条：窗口保留原生三按钮（最小化、最大化、关闭），并用透明可拖动区域承载顶部拖动与双击最大化，外观与 macOS 的隐藏标题条统一（`desktop/main.cjs` 中菜单与标题条按平台分支）。工作台与余时的滚动容器使用 8px 主题滚动条：透明轨道、中性圆角 thumb、悬停少量金色、无上下箭头，浅色与深色主题各自可见。

#### Windows 玻璃材质（明确的取舍，不是无损优化）

Windows 默认走 CSS 通透/磨砂玻璃：保留 rim、tint、通透与磨砂的差别和状态边界，但**不做 SVG 精细边缘位移**（`src/home/glassRendering.ts` 的 `supportsGlassRefraction` 在 Windows 上返回 false）。设置 → 外观与动画 → 玻璃渲染可改为「精细折射」换回 SVG 边缘位移，代价是帧率明显下降——详见[渲染与后台性能](./PERFORMANCE.md)的 BetaX 表。**黑洞的最高画质、渲染分辨率、采样与辉光不因这一取舍降低**；该取舍只影响玻璃合成路径，不计入同画质性能提升。

### 跨设备同步（共享文件夹 / Syncthing 现有目录）

入口是「设置 → 数据 → 跨设备同步」。选择普通共享文件夹，或选择用户已经用 Syncthing 共享的本地目录（需要 `.stfolder` 标记）。每台设备保留自己的 SQLite，所选目录只传 AES-256-GCM 加密的不可变操作文件；新建组选择新目录，原设备把恢复密钥导出到共享目录之外，新设备选择加入并输入 64 位密钥。

暂停停止目录读写，本机变更继续排队；恢复后按 30 秒周期扫描，支持手动检查并在系统唤醒时检查，最近检查时间会持久化。界面显示待处理原因和最近 20 项事务回执；**回执只表示本机已记录事务，不是远端送达证明**。不同字段的改动自动合并，同字段冲突可保留本机或重新核验传入内容；删除 tombstone 不会复活旧记录，锁定、时间重叠与 DDL 冲突进入待处理。日程仍按整文档内的数组级合并，可能需要人工处理。同步内容为任务、分类、课程日程、安排、目标和完成记录；不传 API Key、模型路径、聊天、记忆、思考、原始对话回执与跨设备撤销，只有业务事务摘要回执。退出组保留本机数据和共享文件；撤销设备必须使用新目录、新密钥和新组，全部可信设备和恢复副本都丢失密钥时，旧密文无法恢复。传输软件由用户自备：ASTaria 不安装、不配置 Syncthing，也不修改防火墙或配对设置；Syncthing 实际跨机传送尚未验收，目前只验证了目录协议与标记。限制与未验收：单次操作 16 MB、单轮 20000 个文件、日志不压缩；超过限制或多设备大量数据未验收。不得共享 SQLite、WAL 或 SHM 文件。

## 发布清单签名（维护者）

自动更新要求发布清单使用与 `desktop/releaseTrust.mjs` 内置公钥配对的 Ed25519 私钥签名。私钥保存在仓库外，不提交、不上传、不随 App 分发。保管并备份同一密钥；丢失或更换密钥需要先设计旧客户端可信的迁移。不传 `--sign-manifest` 的清单只适用于手动分发测试包，无法通过自动安装校验。公开 Release 上传前须对实际清单执行 `verifyReleaseManifest`，并核对 DMG SHA-256、App CDHash、源码提交和干净状态。

Windows Release 清单同样必须先签名才能用于应用内更新：`scripts/package-windows.mjs` 只产出清单，需要再用现有 `scripts/sign-release-manifest.mjs <manifest.json> <private-key.pem>` 以固定私钥 `wason-2026-01` 签名，私钥须与 `desktop/releaseTrust.mjs` 内置公钥配对。Windows 打包器本身不带签名参数。未签名的清单（旧本地测试包即如此）只能手动分发安装，无法通过应用内更新的验签，不能作为应用内更新的来源。
