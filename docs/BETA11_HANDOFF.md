# Beta11 交接约束

更新于 2026-10-05。这里保留用户已明确的决定，避免换人或换会话后重新猜测。实现/验收状态以 [Beta11 说明](./RELEASE_NOTES_v0.1.0-beta.11.md)、[性能记录](./PERFORMANCE.md)和 [PROJECT_ROADMAP.md](../PROJECT_ROADMAP.md) 为准。

- Beta11 同时优化 macOS 与 Windows，分别构建、分别实机验证。重点是切换页面和展开聊天的卡顿；尽量保持既有画质和 ASTaria 风格，不能用降质或取消省电约束冒充同质量收益。
- 首次进入应有帧率、画质和 ASTaria 推荐选项；工作台空态教程不要求点击不存在的事项。已有 BetaX 修复需保留。
- 首页/聊天沿用手动帧率，工作区环境渲染最高 60 FPS 是用户明确确认的省电设计。先读[省电与渲染决策记录](./POWER_AND_RENDERING_DECISIONS.md)，再做性能修改。记录每版优化的传统继续保留，不能只留最新结果而丢掉设计原因。
- 本轮只生成本地测试包，**不要推送 GitHub、创建发布 tag 或上传 Release**。早先 BetaX 的上传授权不适用于本轮 Beta11。
- 用户已手动修改 GitHub Release 说明以统一格式（2026-10-05）。将来获得发布指示后，先读取届时线上 Release 的最新正文与格式，再按其结构增补；不要直接用本地旧说明覆盖人工编辑。当前未读取/比对这次线上编辑，也未更改线上内容。
- Windows 当前只有 Windows 10 测试环境，Windows 11 未验收；不能将单机结果写成全平台已通过。
- 用户暂不允许下载本地模型，不能安装/下载 Ollama 或模型来补齐验收；真实模型下载与工具调用仍须如实保留验收缺口。
- 性能验证使用临时 profile 与数据库。构建和安装验收使用独立目录，保留真实数据；macOS DMG 只提供 Applications 快捷方式，不自动复制进 Applications。

后续改变以上约束时，应同时更新相应决策原因、源码注释、回归检查和本版说明。未知的历史理由须标为待核对，不推测为用户决定。
