# ASTaria

源码采用 [Apache-2.0](./LICENSE)；第三方依赖保留各自许可。该许可证不授予 ASTaria 名称或标识的商标使用权，见 [NOTICE](./NOTICE)。

ASTaria 是以析熙为伴的个人时间与事项应用。黑洞首页连接对话、日程、余时和专注工作台；事项、安排、对话与记忆保存在本机，模型可以在真实空档中安排任务，并留下可核对、可撤销的变更回执。

- **工作台**回答「现在怎么做」：开始专注、逐步完成事项，记录下次继续的接力。
- **日程**回答「现在要做什么」：一起查看课程、固定活动、截止时间与具体任务时段。
- **余时**回答「未来想做什么」：持续学习目标按真实空档推进；弦轨让用户先调整日期与顺序，再按真实空档在本机安排具体时间。

默认进入黑洞首页，事项界面可从 `/#/app` 进入。首页、工作台与日程共享析熙对话、本机任务和记忆。`0.1.0-beta.4` 面向 macOS Apple Silicon 的小范围内测；尚不是正式版。

累计功能与修复见[更新记录](./CHANGELOG.md)，本轮实际结果见[发布说明](./docs/RELEASE_NOTES_v0.1.0-beta.4.md)。安装包与版本说明见 [v0.1.0-beta.4 Release](https://github.com/Wason-dev/ASTaria/releases/tag/v0.1.0-beta.4)。

```bash

npm run build   # 类型检查 + 生产构建（输出到 dist/）
npm run build:preview # 设计预览构建（不注册新的离线缓存）
```

外观统一从「设置 → 外观与动画」调整。专注与休息时长在所有构建中均可调整。

## 析熙与本机数据

从源码开发需要 Node.js 24.19 或更新的 Node 24 版本（使用内置 `node:sqlite`），以及 macOS Command Line Tools。开发和本地预览服务都提供同源 `/api`，请保持服务运行；单独打开 `dist/index.html` 或把静态文件托管到远程并不包含本机服务。桌面包需要同时包含页面、本机服务和预编译的钥匙串助手，不能只把网页套进窗口。

```bash
npm run dev -- --host 127.0.0.1 --port 5177
# 或构建后预览
npm run build:preview
npm run preview -- --host 127.0.0.1 --port 5188
```

在左上角 ASTaria → 设置中输入 DeepSeek API Key，选择「保存到钥匙串」，再「测试连接」。密钥通过本机私有管道写入 macOS 钥匙串，账号为 `dev.wason.ASTaria.deepseek / api-key`；不写入 `.env`、Git、SQLite、浏览器存储，也不向前端回显。服务固定请求 DeepSeek 官方 HTTPS 地址。源码开发时首次使用会编译本机钥匙串助手，桌面包已包含预编译助手；系统可能请求钥匙串访问授权。测试连接会产生少量 API 用量。

也可以在「设置 → 析熙 → 连接模型」切换到本地模型。支持本机 Ollama、LM Studio 和 OpenAI 兼容服务；地址只接受 `127.0.0.1`、`localhost` 或 `[::1]`，可读取已加载模型，也可手写模型名。连接地址与设备详细信息默认收起。保存后用「测试连接与工具」执行一次工具调用往返检查；没有通过工具调用的模型只适合普通问答，不应承担修改任务或日程。设备建议按系统内存估算，不测推理速度，也不会在本地失败时偷偷切回云端。首次切换本地会按设备内存预选 Qwen3 4B / 8B / 14B / 32B，已保存的自定义模型不被替换；未确认安装的推荐型号不会自动变成可用连接。本地建议至少 32K 上下文，仍可选择其他支持工具调用的模型。

Ollama 用户可展开「还没有模型？帮我安装」，从 Qwen3 4B / 8B / 14B / 32B 中选择。下载前展示预计下载量、磁盘需求与内存建议，确认后由本机 Ollama 下载，支持进度、取消与重新打开设置查看；完成后再次读取已安装列表，核对成功才允许选用。下载不会自动切换当前模型。取消可能保留 Ollama 的下载缓存；ASTaria 服务重启后需重新检测，已安装文件仍由 Ollama 管理。尚未安装 Ollama 时提供官方下载入口，需要用户安装并打开运行时；LM Studio 与其他兼容服务仍由其自身管理模型下载。回归测试使用模拟服务，不会真实下载模型。

设置中的默认模型可选择 DeepSeek Flash 或 DeepSeek V4 Pro，初始为 Flash，选择保存在本机数据库并跨浏览器共享。思考深度默认 Max，可选 High、Low 或关闭；设置直接传给 DeepSeek，工具调用轮次会原样保留模型返回的 reasoning_content。聊天按 Enter 发送、Shift+Enter 换行，中文输入法确认候选字不会误发；自己的消息即时显示，失败后可重试。析熙可以提出带快捷选项的问题，也支持自由输入回答。消息可复制，自己的消息可撤回；撤回后停止该轮后续处理并排除相关上下文，已执行的事项变更仍可从回执单独撤销。

「流式输出」默认开启，可在同一连接设置中关闭。思考过程与回复逐步显示，思考区可折叠；这些是模型实际返回的内容，本地模型是否返回思考字段取决于服务。生成中的文字不代替执行回执，最终以已保存状态为准。网络中断保留原请求 ID 和已保存进度，重试不会重复执行已完成的操作。开关从下一条消息生效，不改变正在执行的请求。

黑洞渲染档位位于「设置 → 外观与动画」：满特效 120、满特效 90、满特效 60、轻特效 45、低特效 30。满特效档保持完整折射与 Bloom，低档保留整体视觉语言并降低渲染预算。首页与首页聊天按所选帧率运行；工作台及其他子页面自动将目标限制为 60 FPS。实际帧率受显示器刷新率与设备性能限制，页面隐藏时渲染会自动暂停；测试浏览器应在验证结束后退出，避免后台残留持续消耗 GPU。

数据存放于 `~/Library/Application Support/ASTaria/astaria.sqlite`，目录权限 0700、数据库 0600。同一 macOS 用户下的浏览器共用此文件。SQLite 保存任务、分类、日历、安排、对话、记忆、摘要、变更回执、推演、接力和正式设置；正在进行的专注计时与开发调参仍保存在浏览器中。旧浏览器业务数据首次打开后幂等迁移，源数据保留，旧 API 设置不会导入。若曾在旧界面保存过 API Key，请在迁入钥匙串后清理旧的 `astaria-settings` 浏览器数据库，并按需在 DeepSeek 控制台轮换旧密钥。

析熙可读取和拆分事项、设置截止与计划时间、修改状态、记住有原话来源的偏好。每次修改有回执，可以撤销；之后被手动改过的记录会保护性拒绝覆盖。临时记忆带有效期，任务记忆只用于相关任务。设置中可查看来源或忘记；相关来源及衍生上下文会被排除，原始聊天仍供回看。长期聊天使用有来源的摘要加最近完整轮次，并按需检索旧对话。

「设置 → 析熙」可调整个性强度：低（简洁温和）、中（自然俏皮）、高（有主见，嘴硬一点，做事认真），默认高。高档只在轻松语境里偶尔顶一句，关心落在具体回应和行动上；用户难过、着急或纠错时收起打趣。保存后从下一条回复开始生效，不必新开对话；各档只调整表达，与主动权限、提醒频率、记忆开关独立。设置随本机数据持久化并进入备份。

人格底色位于 `server/prompts/persona.md`，三档表达由 `server/personality.mjs` 按当前设置选取，工作与工具协议位于 `server/prompts/working.md`。请求时按需选取对话、记忆、任务与日程资料交给 DeepSeek。测试使用虚拟 provider 和临时数据库，不需要真实密钥或付费请求。

上下文在每次实际请求前统一计算预算，包含实时钟表、工具定义和待完成事项。较长的旧对话与工具结果只压缩发送副本，原文保留在本机；省略的读取明确标记为未读全，不能当成空闲。多项明确时段分别核验；中断提示列出已保存与尚未完成的部分，重试接续原请求。全部已核验的排程即使最后文字回复超限，也可用本地回执确认，不重复执行。

析熙新建事项后会直接根据真实空档安排日历，不再先问是否安排。按已有估时分配；未给用时时先预留 30 分钟，并注明可修改。安排避开课程、休息、已有任务和锁定时段，遵守明确日期、可用窗口及截止时间；空档不足会列出剩余未安排部分。“只记录、先不安排”和设置中的“先提出方案”仍会保留原日程。任务和本次自动安排在同一事务提交，撤销创建也会撤销关联的自动时段；后续手动修改仍受版本保护。

重复任务由一个 repeat 模板按目标日期展开，每个日期独立记录进度，只在当天安排一段完整时长；可优先放到指定窗口的末尾，不把多天任务挤到同一天，也不拆成零碎时段。空档不足会列出未排日期。创建和初次安排合并为一个公开回执，可一起撤销。

工作台「现在可以开始」以真实日程块判断：没有具体时间的事项可直接开始；有具体安排的事项在开始前 20 分钟才进入。已过时段但尚未完成的事项会标注可继续。无明确截止的列表默认折叠；已完成默认只显示最近 7 天并分页，完整历史支持搜索与日期筛选。

指定钟点的新事项可通过 `create_tasks` 的每项 `schedule` 与 `expectedRevision`，在读取日程后把事项和时段一起保存；冲突时一起回滚。兼容分步创建的调用，每项日历义务独立核验：移动考试成功不能代替社团活动入历，明确日期和时段按实际记录检查。未完成时继续执行，失败保留重试，撤销后的安排不会自动复活。默认日程上下文将“晚自习”等窗口与占用者、实际剩余时间一起提供；后续日程和截断计数保持可辨，全天占用分钟数不代表某个任务的用时。

聊天的创建事项回执下方只保留 DDL 和预估时间快捷设置。预估时间支持 15 / 20 / 30 / 45 / 60 分钟、自定义和清除，修改只更新任务估时，不会偷偷伸缩已有日程。DDL 提供「今天／明天／后天／日期与时刻」，直接修改原事项的 DDL；可快捷选择 08:00、12:00、18:00、20:00 或全天，也能自定义分钟和清除日期，不需要再次聊天或重新创建。更新同步工作台与日程；若新 DDL 早于已有时段，会提示调整计划。每轮工作单分别记录工具提交、未完成部分和回复状态；已提交的完整操作遇到回复生成失败时，会用本地事实回执收口。

## 日程与安排

从左上角 ASTaria 进入「日程」。月视图观察截止日期与忙闲分布，周视图显示课程、固定活动、休息、空课与任务时段，日视图展开一天的完整时间线。月／周／日切换保留选中的日期，并展示对应日期的可支配时间与出门准备。任务的截止日期和安排时段分别保存，移除时段会保留任务。旧启动设置中的日历、时间表自动映射到日程。

导航始终向右展开，窄屏可在栏内横向滚动，也可用方向键、Home／End 导航。日程页面将当天信息集中在顶部横向概览，下方主视图使用整行宽度；需要与析熙对话时可返回首页。时间表中的空课用金色边框表示，点击整块或按 Enter／空格即可编辑。临时调课日也可点击课程、休息或空课编辑来源的每周安排，窗口会说明影响范围；保存后同步今天和未来的相关调课日，历史记录保持不变。来源已被移除时保留历史只读内容，并提供当前每周安排入口。

日程按内容完整展开，统一滚动整个页面查看下方日期与晚间时段，主玻璃板内部不再上下滚动。窄屏的周视图保留横向滚动；日视图使用单列时间线。

首次使用默认加入周一至周五 18:00–20:00 晚自习，可自行修改，也可自己录入课程、空课与时间。未记录的空白不计为空闲，可支配时间只统计明确的空课或自习，并扣除固定活动、休息及已安排任务。核对完成后可点击「已核对完成」，之后仍可编辑每周安排。每周安排可选择每周、单周或双周，并明确指定第 1 周的周一；周次跨年连续计算。单日调课使用目标日期所在周的课表，历史快照保持原样。旧课表默认为每周。

点击课程可记录地点及所需物品；点击任务可填写准备说明、携带物品、是否需要提交，并添加或锁定时段。出门清单会汇总当日需要的物品，保留来源及「建议」标记。完成任务与确认提交是独立状态：已经做完但还没提交的事项仍会提醒，实际提交由用户确认，也可撤回确认。

任务指定钟点或修改现有计划时，析熙通过 `read_planner` 读取目标日期起最多 7 天的安排，再用 `plan_tasks` 保存时段。任务排程会检查日期版本、时区、过去时间、重叠、DDL 和锁定状态；未知空档需先确认，锁定时段需用户在页面解锁。AI 的 `startAt` 仅表示日期意向，精确钟点由排程工具处理。多个任务顺延可同批提交，按最终布局检查冲突并原子保存，可整体撤销；排程回执返回实际保存的时段。`remove_plan` 移除未锁定时段，`save_task_preparation` 保存明确的准备信息，操作均提供可查看、可撤销的回执。

已确定日期和钟点的会议、校庆、临时课程等作为单日活动保存，独立于任务与每周课表。析熙读取目标日后通过 `save_day_events` 一次记录多项活动；活动可以跨越可用时段边界，已有重叠会明确返回，不会覆盖原计划或改动每周模板。首页与日程都显示活动并支持直接编辑。保存、删除、重试与撤销使用版本校验和工作单核验，完成回复以当前实际记录为准。未能写入时如实说明失败，不再反复注入相互矛盾的强制排程指令。

站内可见页面会根据未读变更、真实空闲和准备清单显示通知。在 macOS App 的「设置 → 通知」可另外开启系统提醒：课程、单日活动和已安排事项提前 5 分钟，明确时刻的 DDL 提前 30 分钟，仅日期的 DDL 当天 20:00。提醒遵循免打扰时段，已过提醒时刻不补发。

系统提醒默认关闭，需允许「ASTaria 提醒」发送通知。未来 30 天内最近的 64 条预约交给 macOS，关闭窗口或退出 App 后仍可触发；修改、完成、删除后会更新预约，关闭开关会取消。打开 App、恢复使用和运行期间的定期同步补充后续提醒，长期不打开时不会超出这批预约继续生成。系统权限、专注模式和关机影响送达。定位、设备感知和析熙立绘尚未接入。

## 余时、弦轨与接力

从左上角 ASTaria →「余时」管理持续学习目标。可设置优先级、每周最低频率、单次时长偏好和阶段目标，默认单次20–40分钟，可自行调整。每个目标只关联一个长期事项；日历保存具体学习时段。新目标保存后安排未来七天，之后每天首次打开应用补充安排，按实际空档分散到不同日期、避开现有事项并留出休息。暂停不再新增安排；频率无法满足会显示缺口。过去的安排不算完成，用户逐段记录完成、学习反馈和下次接着做的内容。撤销排程保留目标且当日自动补排不会复活已撤销的时段。

析熙可通过 `read_free_time` 读取目标、时段与反馈，使用 `save_free_time_goal` 调整重点、频率和时长，通过 `schedule_free_time` 补排，并用 `complete_free_time_session` 记录某次学习完成而不结束长期目标。旧牵挂和合适时机并入余时的待考虑区域，显式加入后才成为自动安排的目标。

点击首页右侧黑洞或余时的「弦轨」入口，镜头靠近事件视界边缘，停在一条有厚度与流动纹理的地平线上。今天、明天、后天逐日查看，组名常驻；点开组后，事项沿同一条地平线展开。「收拢这组」回到组视图，退出沿原路回拉。弦轨外观统一在「设置 → 外观与动画」调整，场景内不再放开发调试入口。

弦轨读取这三天内**已经安排但尚未完成的真实任务段**。今天原定时间已过、仍待办的事项也会显示，标记为待重新安排；真正处于进行中且已经开始的事项、锁定段保留在固定安排中。未排进日历的待办不会自动加入轨道。

首次进入尚未保存分组的日程，先显示本地按目标和分类整理的初稿，再由当前模型按实际内容与共同目标智能分组。不同日期分开，每组最多 6 段；不因同一学科或都属于生活事务就硬凑。智能建议只改草稿，日程未变时两分钟内复用结果。已保存的分组会保留，想重整时可点「智能整理」。模型失败会说明原因，仍可使用原分组手动调整。

拖动组调整当天顺序，拖到顶部日期可整组换天；展开后可以调整组内顺序。键盘方向键也可排序，Alt 加方向键换天。「调整分组」支持改名、拆出事项、合组和跨组移动；手动调整后先完成保存，避免智能建议覆盖草稿。重复事项遵守原日期，其他事项仍受 DDL 和余时目标日期约束。组再多也会分页完整保留。

分组编辑使用单片玻璃和行分隔，继承全局通透／磨砂设置。打开时后方文字淡出、光带降低亮度，黑洞场景仍然保留；返回弦轨时恢复。

点击「完成」才提交草稿。三日弦轨先在本地检查真实空档、连续用时和截止时间，生成符合所选日期、组序和组内顺序的初排，再由当前所选模型用一次请求微调具体时刻。只发送必要的排程信息，模型只返回需要改变的起点；云端智能分组和排程的思考深度最高为 low，不更改聊天设置，本地模型仍使用当前连接。进度贴合地平线，显示实际读到的事项数量、每天的用时与空档、模型返回的具体建议、终检和保存；可展开活动记录，并显示已等待时间，不展示内部推理或虚构工具调用。

模型返回后重新核对日程版本、固定占用和全部约束，全部通过才整批保存，分组随日程一起持久化，保留原任务段与完整时长，并提供撤销回执。仅改名或同布局分组标识变化时保留原时间，无需模型排程；未改动、重复完成和明显无解的草稿也无需再次调用模型。今天有待重新安排的过时段时，即使未拖动也会执行排程。如果等待模型期间合法初排起点刚过去，会按当前空档更新并再次完整校验；真实日程变化仍须重新读取。模型超时、失败或校验失败均保留原日程，不静默回退或写入部分安排。一次提交目前最多调整 128 个可移动任务段；七日普通弦轨保留原模型排程路径。

专注页按计时、任务步骤、析熙聊天排列。在右侧聊天粘贴作业要求，析熙可以把当前任务拆成可勾选的步骤，保留每一步的材料与提交要求。中间清单显示完成数量、进度和下一步，较长清单分页查看。勾选或取消勾选后立即存入本机数据库，再次进入、刷新或换浏览器都会恢复；重新拆分保留已有进度。明确给出当前任务的具体明细时，析熙直接保存对应步骤，条目数量与顺序按用户提供的内容保留。全部勾选不会自动完成整项任务或确认提交。析熙写入步骤有可撤销回执，后续手动勾选会保护进度，阻止旧回执覆盖。

左侧玻璃板在专注和接力之间切换，中间始终保留任务步骤。点击与专注按钮并排的金色药丸「留个接力」会暂停计时，在同一面板记录进度、卡点、下一步和材料；保存后回到计时界面并显示接力摘要，继续计时由用户决定。返回专注会保留未保存草稿，已保存的记录下次进入可恢复。切换只移动玻璃内部内容，玻璃本身保持不动。接力与牵挂保留原话来源和版本，AI来源撤回时衍生记录退出上下文。

余时中的待考虑清单保存尚未成为任务的愿望，可编辑、暂停、恢复、移除或设置有效期。机会提示依据真实空闲，所需物品及其他条件仍需用户确认；未提供用时时暂按30分钟试留并注明估计。它不会自动创建任务或占用日程。点「聊清楚」可在原有析熙对话里逐步明确动机、第一小步和条件；确认后的补充写回同一份心愿。澄清草稿与普通聊天草稿分别保留。明确选择加入余时后才成为自动安排的目标，原心愿暂停留意，避免重复推荐。

## 设置与黑洞回应

设置使用独立页面，分为通用、析熙、时间安排、通知、外观与动画、数据。「析熙」统一管理模型连接、个性、主动程度与记忆；记忆明细默认收起，可翻页查看来源、更正或忘记。通知页左侧为提醒设置，右侧为变更记录，可按全部、未读、已读、已撤销筛选；每页四条，详情按需展开，撤销在对应记录右上角。其他设置包括启动页面、默认专注休息、排程缓冲、晚自习和周末可安排时段、免打扰、网格、玻璃预设和信息密度。数据页提供无 API Key 的 JSON 备份和显式确认恢复，恢复会使旧方案及旧操作快照失效。

「外观与动画 → 玻璃与空间 → 卡片装饰线」提供左右对称、仅左侧、隐藏，默认左右对称。课程、安排和同类小卡片沿用各自状态色，金色可安排框和选中轮廓保留；设置保存在本机数据库并跨浏览器共享。

「外观与动画」提供光潮、弦光、引星、关闭，以及轻柔/标准/鲜明强度和减弱动态。默认光潮·轻柔。「思考时显示数字」独立控制黑洞内部的数据流：小号、竖直排列的 0 与 1 持续下落，采用接近黑色的中性灰与轻微景深层次，不再金色闪烁；数字限制在黑洞轮廓内，边缘平滑淡出。只在析熙思考时出现，开始回复后继续下落并在约 1.2 秒内淡出，减少动态时缩短变化。该层沿用原黑洞渲染和后期管线，不额外建立全屏渲染链。

预览时收起设置内容以展示黑洞，返回时通过退场动画恢复原滚动位置与焦点，退场同时释放玻璃折射和阴影。预览不调用模型；实际聊天由思考、执行与回复状态驱动视觉。关闭盘面回应与关闭思考数字是两个独立选择。外观设置保留必要的样式、强度、数字开关和动态选项，底层兼容参数不全部暴露为调试控件。

模型偶尔将提问工具输出为 DSML 文本时，服务会将完整的单个提问恢复为问题与快捷选项。截断、混合或未知的协议内容会显示可读错误，不执行文本中的写操作；旧消息读取时也会修正显示，保留原始存储。

上下文组装优先保留当前请求和相邻四轮对话，再分配次要资料的空间。历史工具负载转换为精简操作记录，保留任务 ID 与问题选项；较长原文保留检索来源，撤回、忘记和关闭历史使用的边界继续生效。


网页生产构建会在 `dist/` 生成 `manifest.webmanifest` 与 `sw.js`（generateSW 产物）；桌面构建不注册这套 PWA 离线缓存。

## macOS 内测与发布范围

本轮面向 macOS 13+ Apple Silicon（arm64）Mac 制作 beta 包。桌面运行时采用 Electron 44.1.0，内含 Node 本机服务、预编译的钥匙串助手和系统提醒助手。构建机需要 Apple Silicon Mac、arm64 Node.js 24.19+（Node 24 系列）、Command Line Tools 和独立取得的干净 Electron.app 及其 LICENSE、LICENSES.chromium.html；应用运行时不应依赖开发服务器或系统 Node。测试范围见[发布说明](./docs/RELEASE_NOTES_v0.1.0-beta.4.md)。

```bash
npm ci
npm run build:desktop
node scripts/third-party-notices.mjs
npm run package:desktop -- --runtime /path/to/Electron.app --out desktop-builds
```

打包器拒绝覆盖同版本产物，只复制指定源码和构建文件，编译并随包放入钥匙串及提醒助手、Electron/Chromium 许可和 [第三方依赖许可清单](./THIRD_PARTY_NOTICES.txt)，然后完成 ad-hoc 签名、压缩和 SHA-256 清单。`--runtime` 必须指向 arm64 Electron.app，Electron 的两份许可文件须与它同目录。打包不包含个人数据库、密钥、环境文件或测试日志。包与校验文件见 [v0.1.0-beta.4 Release](https://github.com/Wason-dev/ASTaria/releases/tag/v0.1.0-beta.4)。

以上命令默认将新产物写入 `desktop-builds/ASTaria-0.1.0-beta.4-mac-arm64/`。版本 Release 提供 DMG、SHA-256、安装说明和记录源码提交的构建清单；本机开发产物留在被 Git 忽略的 `desktop-builds/`。应用使用层叠三瓣 SVG 图标及透明顶部拖动区；图标生成方法见 [图标说明](./design/icon-vector/README.md)。

小范围测试 DMG 包含 App、Applications 快捷方式及中文安装说明；不含开发者的课表、事项、析熙聊天、记忆、数据库或备份。先退出旧版，再将 App 拖到「应用程序」。App 和 DMG 均为 ad-hoc 签名、未公证；若被 macOS 拦截，先核对来源和校验值，优先使用「系统设置 → 隐私与安全性 → 仍要打开」。[安装说明](./docs/INSTALL.md) 另附只针对此 App 的终端命令。

2026-09-29 分两版交付：beta.3 增加可校验的下载与重启安装、工作台余时单次安排入口，并继续减少后台轮询和绘制分配；beta.4 增加隔周课表、macOS 预约提醒和心愿澄清。工作台、日程、余时的单次完成／撤回以及跨日隔离已通过真实页面验收；清透／磨砂设置、更新失败重试与取消、安装失败回退均已验证。完整范围见[发布说明](./docs/RELEASE_NOTES_v0.1.0-beta.4.md)，性能测量见[性能说明](./docs/PERFORMANCE.md)。干净机器、休眠恢复和长期功耗仍需继续测试。

备份导出与恢复已统一为格式化 JSON 的 32 MiB UTF-8 字节上限，超限明确拒绝且不改动本机数据，不再导出无法恢复的超限文件。中文字节、精确上限、超限拒绝与失败原子性测试已通过。恢复会更新状态，之后的新备份仍会重新核验大小。

桌面端沿用 `~/Library/Application Support/ASTaria/` 的本机业务数据。首次运行前应从「设置 → 数据」导出备份，并保留原备份文件；浏览器保存的专注计时、外观调参等状态不等同于 SQLite 数据，不应假定会自动复制进桌面容器。DeepSeek 密钥继续由 macOS 钥匙串管理；若使用本地模型，Ollama 或 LM Studio 仍需在本机运行。

「设置 → 通用 → App 更新」支持检查 GitHub 发布、查看更新说明及下载匹配芯片架构的 DMG。自动检查默认开启，App 可见时最多每六小时检查一次，也可关闭或手动检查；遇到 GitHub 限流会退避，不反复请求。检查仅读取公开版本信息，不发送课表、聊天或模型密钥。Beta 安装可接收后续 beta 和正式版，正式版只接收正式发布。同版本替换包通过更晚的 App 构建时间和不同源码提交识别，编辑 Release 说明不会触发更新。

从 beta.3 起，可在设置中「下载并校验」后选择「安装并重启」。下载支持取消；安装前核对 SHA-256、包大小、App 身份、架构、构建记录和代码签名，原应用在新版本启动成功前保留，失败会尝试回退。本机数据不随 App 替换。旧版尚无安装更新功能，需要先手动安装 beta.3 一次。App 必须位于可写目录；直接从 DMG 或受系统隔离的临时路径运行时，请先复制安装。发布须同时上传匹配的 DMG 和构建清单。

当前不承诺 Intel Mac、Windows、iOS 或 Android 原生包，也未提供关闭应用后的系统后台提醒。个人内测可以使用 ad-hoc 签名；对外分发应完成 Developer ID 签名、公证和干净机器验证，不能把关闭系统安全保护作为安装步骤。实际帧率、休眠恢复与长期功耗需要在目标设备测量。
