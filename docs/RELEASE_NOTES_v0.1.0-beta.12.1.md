# Beta12.1 · 0.1.0-beta.12.1

Beta12.1 修复首页和工作台「专注」的图片输入布局，以及从展开的首页聊天进入工作区时过早降低背景帧率的问题。适用于 macOS 13+ Apple Silicon 和 Windows x64；Windows 仍为未签名试验包，既有卡顿反馈继续保留。

## 聊天输入与拖图

两处聊天均移除输入框上方的「图片」工具栏，在「发给析熙」左边放置圆形 ＋，点击后选择图片。没有附件时恢复原有简洁输入形态；选择图片后在输入框下方显示可移除的预览，读取中或读取失败时在同一位置显示状态或错误。圆形边线、图标、悬停和焦点继承 ASTaria 深浅主题，兼容通透与磨砂。

图片可以直接拖入 ASTaria。工作台专注聊天打开时交给当前事项，保留事项上下文；其他普通页面打开首页聊天。图片只进入预览，仍需主动发送。设置、引导和忙碌状态不接受拖入；拖动文字保留原行为。

选图与拖图共用格式和大小检查：每条消息一张 PNG、JPEG 或 WebP，最大 2 MB。读取期间阻止发送；替换失败清除旧图片，避免下一条文字误带旧附件；较早的异步读取无法覆盖新选择。图片继续保存在本机对话和备份中，不进入共享目录操作同步。所选模型必须支持视觉输入，真实模型识图尚未验收。

## 转场与省电时机

Beta12 根据目的页面立即降到 30 FPS，导致首页展开聊天切入工作区时相机动画被提前降帧。现在以相机弹簧的真实运动状态为准：相机运动期间维持所选首页预算（推荐 60 FPS，手动 30/45/60/90/120），直到停稳才应用工作台、余时、日程、设置最高 30 FPS 的省电策略。中途反向和恢复窗口按实际状态重新判断，不用固定延时或提前可输入阈值替代动画完成。

预算切换不重置场景时间、相机位置或速度；采样、分辨率、辉光、独立画质及 Windows 玻璃选择不变。转场期间会比错误的 30 FPS 预算多绘制背景帧，这是响应性与瞬时负载的取舍；没有本版功耗、续航或 GPU 收益百分比。浏览器记录的目标预算也不等于真实设备持续达到该帧率。

## 更新与验证

两端打包和更新检查支持完整补丁版本号。macOS 的内部构建序号保持 Beta12 → Beta12.1 → Beta13 的递增顺序；用户看到的版本仍为 `0.1.0-beta.12.1`。标准 Windows 安装沿用已签名清单与文件哈希验证，便携版仍手动更新。

全量源码测试 **1,535 项通过**，桌面网页构建、文档版本和第三方许可一致性检查通过。隔离浏览器 **64 项补丁检查通过**，覆盖两处聊天的文件选择、拖图、事项上下文、读取竞争和失败、深浅主题、通透/磨砂、窄屏以及 60/120 FPS 转场预算；README 截图捕获另有 **59 项检查通过**，覆盖真实保存、撤销、调休日程与工作台专注聊天。两者均使用临时浏览器、内存数据库和脚本模型，不代表真实模型识图或 Windows 原生体验。已发布资产的 SHA-256、来源提交、CI、macOS 冒烟和 Windows 包内容核验见 [Beta12.1 验收记录](releases/beta12.1-acceptance.json)。

## 保留的限制

- Windows 当前包的实机安装、切页与展开聊天体验、Windows 11、真实应用内升级/失败回退、另一台电脑及长期功耗尚未验收。CI 成功不能替代这些结论。
- macOS 使用 ad-hoc 签名、未经 Apple 公证；Windows 未做操作系统代码签名。发布清单的 Ed25519 签名与系统代码签名不同。
- Windows 当前只有 App 内提醒摘要和状态，不提供原生系统弹窗预约。
- 搜索无正文时的固定兜底、临时调课后自动重排全部余时、同步目录后续优化、真实 Syncthing 跨机传输、实际本地模型下载/推理/工具调用/识图仍未验收或完成。
- 玻璃静止几何复用不等于独立可变刷新率；黑洞运动的工作区不能整体达到 0 FPS。
