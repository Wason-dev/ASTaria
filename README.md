# ASTaria

React + Vite + TypeScript + Three.js 应用，默认进入黑洞首页，包含本地事项、日程、平行宇宙和专注工作台。
原有业务界面可从 `/#/app` 进入。首页、工作台与日程共享析熙对话、本机任务和记忆。

## 技术栈

| 关注点 | 方案 |
| --- | --- |
| 框架 | React 19 + TypeScript |
| 构建 | Vite（`tsc --noEmit && vite build`） |
| 样式 | Tailwind CSS（`@tailwindcss/vite` 插件，`src/index.css` 中 `@import "tailwindcss"`） |
| PWA | vite-plugin-pwa，`strategies: 'generateSW'`（Workbox 生成 service worker），`registerType: 'autoUpdate'` |

## 命令

```bash
npm install     # 安装依赖
npm run dev     # 本地开发服务器
npm run build   # 类型检查 + 生产构建（输出到 dist/）
npm run build:preview # 带视觉自定义与示例数据入口的设计预览构建
npm run preview # 预览生产构建产物
npm run typecheck
npm test        # 领域模型、本地数据库、AI 上下文和本机 API 的测试
```

视觉调参和示例入口仅在开发服务器或 `build:preview` 中启用，正式构建不读取已保存的调试外观参数。专注与休息时长属于正式功能，两种构建均可调整。

## 析熙与本机数据

需要 Node.js 24.19 或更新的 Node 24 版本（使用内置 `node:sqlite`），以及 macOS Command Line Tools。开发和本地预览服务都提供同源 `/api`，请保持服务运行；单独打开 `dist/index.html` 或把静态文件托管到远程并不包含本机服务。

```bash
npm run dev -- --host 127.0.0.1 --port 5177
# 或构建后预览
npm run build:preview
npm run preview -- --host 127.0.0.1 --port 5188
```

在左上角 ASTaria → 设置中输入 DeepSeek API Key，选择「保存到钥匙串」，再「测试连接」。密钥通过本机私有管道写入 macOS 钥匙串，账号为 `dev.wason.ASTaria.deepseek / api-key`；不写入 `.env`、Git、SQLite、浏览器存储，也不向前端回显。服务固定请求 DeepSeek 官方 HTTPS 地址。首次使用会编译一个本机钥匙串助手，系统可能请求钥匙串访问授权。测试连接会产生少量 API 用量。

设置中的默认模型可选择 DeepSeek Flash 或 DeepSeek V4 Pro，初始为 Flash，选择保存在本机数据库并跨浏览器共享。当前使用非思考模式。聊天按 Enter 发送、Shift+Enter 换行，中文输入法确认候选字不会误发；自己的消息即时显示，失败后可重试。析熙可以提出带快捷选项的问题，也支持自由输入回答。消息可复制，自己的消息可撤回；撤回后停止该轮后续处理并排除相关上下文，已执行的事项变更仍可从回执单独撤销。

黑洞渲染档位位于「设置 → 外观与动画」：满特效（60 FPS）、高刷 90、高刷 120、平衡（45 FPS）、省电（30 FPS）和极省电（20 FPS）。高刷档保持最高画质，实际帧率受显示器刷新率限制；低档保留黑洞、折射、Bloom 和整体视觉语言，降低渲染分辨率、星尘预算与刷新频率。页面隐藏时渲染会自动暂停，测试浏览器应在验证结束后退出，避免后台残留持续消耗 GPU。

数据存放于 `~/Library/Application Support/ASTaria/astaria.sqlite`，目录权限 0700、数据库 0600。同一 macOS 用户下的浏览器共用此文件。SQLite 保存任务、分类、日历、安排、对话、记忆、摘要、变更回执、推演、接力和正式设置；正在进行的专注计时与开发调参仍保存在浏览器中。旧浏览器业务数据首次打开后幂等迁移，源数据保留，旧 API 设置不会导入。若曾在旧界面保存过 API Key，请在迁入钥匙串后清理旧的 `astaria-settings` 浏览器数据库，并按需在 DeepSeek 控制台轮换旧密钥。

析熙可读取和拆分事项、设置截止与计划时间、修改状态、记住有原话来源的偏好。每次修改有回执，可以撤销；之后被手动改过的记录会保护性拒绝覆盖。临时记忆带有效期，任务记忆只用于相关任务。设置中可查看来源或忘记；相关来源及衍生上下文会被排除，原始聊天仍供回看。长期聊天使用有来源的摘要加最近完整轮次，并按需检索旧对话。

人格方向与示例位于 `server/prompts/persona.md`，工作与工具协议位于 `server/prompts/working.md`。请求时按需选取对话、记忆、任务与日程资料交给 DeepSeek。测试使用虚拟 provider 和临时数据库，不需要真实密钥或付费请求。

## 日程与安排

从左上角 ASTaria 进入「日程」。月视图观察截止日期与忙闲分布，周视图显示课程、固定活动、休息、空课与任务时段，日视图展开一天的完整时间线。月／周／日切换保留选中的日期，并展示对应日期的可支配时间与出门准备。任务的截止日期和安排时段分别保存，移除时段会保留任务。旧启动设置中的日历、时间表自动映射到日程。

导航始终向右展开，窄屏可在栏内横向滚动，也可用方向键、Home／End 导航。日程页面将当天信息集中在顶部横向概览，下方主视图使用整行宽度；768px 及以上唤出析熙时，聊天与主视图并排；更窄时使用固定抽屉，标题和输入框不随聊天记录滚走。Esc 可收起聊天并返回触发按钮，跨尺寸切换保留输入草稿。时间表中的空课用金色边框表示，点击整块或按 Enter／空格即可编辑。

日程按内容完整展开，统一滚动整个页面查看下方日期与晚间时段，主玻璃板内部不再上下滚动。窄屏的周视图保留横向滚动；日视图使用单列时间线。

首次使用默认加入周一至周五 18:00–20:00 晚自习，可自行修改。项目内的旧课表需要点击「载入旧课表」，由用户核对课程、空课与时间，也可自己录入；载入时保留已有晚自习与自行添加的安排。未记录的空白不计为空闲，可支配时间只统计明确的空课或自习，并扣除固定活动、休息及已安排任务。核对完成后可点击「已核对完成」，之后仍可编辑每周安排。目前支持每周重复课表，尚不支持隔周课表。

点击课程可记录地点及所需物品；点击任务可填写准备说明、携带物品、是否需要提交，并添加或锁定时段。出门清单会汇总当日需要的物品，保留来源及「建议」标记。完成任务与确认提交是独立状态：已经做完但还没提交的事项仍会提醒，实际提交由用户确认，也可撤回确认。

析熙通过 `read_planner` 读取选中日期起最多 7 天的安排，再用 `plan_tasks` 将任务放入明确可用时段。安排会检查日期版本、时区、过去时间、重叠、DDL 和锁定状态；未知空档需先确认，锁定时段需用户在页面解锁。AI 的 `startAt` 仅表示日期意向，精确钟点统一由排程工具处理。`remove_plan` 移除未锁定时段，`save_task_preparation` 保存明确的准备信息，操作均提供可查看、可撤销的回执。站内可见页面会根据未读变更、真实空闲和准备清单显示通知；尚不提供关闭应用后的系统通知、定位或设备感知，析熙立绘尚未接入。

## 推演、接力与牵挂

从左上角 ASTaria →「平行宇宙」进入独立页面，与工作台、日程并列。首页和设置不再另放推演入口；聊天中的具体方案回执可直接打开对应方案。可以比较重新梳理、首日休息、轻量三种方案，用日期滑条查看当前日程与候选安排；宽屏也能切到黑洞空间节点，窄屏保留可读时间线。当前是基于明确空闲、DDL、估时和缓冲的本地规则推演，不承诺最优排程；估时缺失、无法满足的截止和未安排工作都会明确列出。预览不改变任务，点击应用后在同一个事务中写入；版本、锁定、DDL或时间变化会要求重新推演。应用后可整体撤销。

专注页的接力现场保存已完成步骤、卡点、下一步和材料。退出后再次进入同一任务可以恢复；「卡住了」准备一段带当前任务的聊天草稿，等待用户发送。「今天先到这」暂停计时并聚焦收尾，不会自动完成任务。接力与牵挂保留原话来源和版本，AI来源撤回时衍生记录退出上下文。

牵挂清单保存尚未成为任务的愿望，可编辑、暂停、恢复、移除或设置有效期。机会提示依据真实空闲，所需物品及其他条件仍需用户确认；未提供用时时暂按30分钟试留并注明估计。它不会自动创建任务或占用日程。

## 设置与黑洞回应

设置使用独立页面，分为通用、析熙、记忆、时间安排、通知、外观与动画、数据。可调整启动页面、自动执行/先提方案、记忆和历史的上下文使用、默认专注休息、排程缓冲、晚自习和周末可安排时段、免打扰、网格、玻璃预设和信息密度。记忆可更正或忘记；变更有未读记录。数据页提供无API Key的JSON备份和显式确认恢复，恢复会使旧方案及旧操作快照失效。

「外观与动画」提供光潮、弦光、引星、关闭，以及轻柔/标准/鲜明强度和减弱动态。默认光潮·轻柔。预览时收起设置内容以展示黑洞，返回时通过退场动画恢复原滚动位置与焦点，退场同时释放玻璃折射和阴影。预览不调用模型；发送消息时对应真实请求的思考阶段，整段回复到达时呈现约4秒回复反馈，随后自然平息。现有API为整段返回，并非流式输出。特效由明确的渲染接口传入，idle/off恢复原始盘面；相机、观察距离、视界形状和鼠标引力不变。

模型偶尔将提问工具输出为 DSML 文本时，服务会将完整的单个提问恢复为问题与快捷选项。截断、混合或未知的协议内容会显示可读错误，不执行文本中的写操作；旧消息读取时也会修正显示，保留原始存储。

上下文组装优先保留当前请求和相邻四轮对话，再分配次要资料的空间。历史工具负载转换为精简操作记录，保留任务 ID 与问题选项；较长原文保留检索来源，撤回、忘记和关闭历史使用的边界继续生效。

## 结构

```
index.html            入口 HTML
vite.config.ts        Vite + Tailwind + PWA 配置（manifest 名称：ASTaria）
tsconfig.json         TypeScript 配置
src/main.tsx          React 挂载入口
src/App.tsx           原有业务界面
src/home/             黑洞首页、析熙面板与日程概览
src/workbench/        专注工作台、Upcoming DDL 与开发预览工具
src/planner/          日历、时间表、空闲容量、任务时段与出门准备
src/xixi/             析熙聊天、设置、记忆与变更记录
server/               本机 SQLite、钥匙串、AI 工具与提示词
src/prototype/        黑洞渲染核心
src/index.css         Tailwind 入口
src/vite-env.d.ts     Vite 客户端类型
public/               静态资源与 ASTaria 图标
```

构建后 `dist/` 中会生成 `manifest.webmanifest` 与 `sw.js`（generateSW 产物）。
